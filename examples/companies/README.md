# 2 社の作り物の答えと、作り物のデータの種

デモに使う 2 社の、立ち上げの質問への答え (YAML) と、作り物のデータの種を置く。2 社とも作り物で、実在しない。

| 答えの YAML | 種のフォルダ | 会社 | ポート |
|---|---|---|---|
| `a_machining.yaml` | `a_machining/` | A 社。機械加工で、注文を送る側 | 8001 |
| `b_plating.yaml` | `b_plating/` | B 社。表面処理で、注文を受ける側 | 8002 |

## 答えの YAML

1 つのファイルが 1 社の答え。鍵の意味は、ファイルの中の 1 行のコメントに書いた。

| 鍵 | 書く物 |
|---|---|
| `id` | 会社の id。ファイル名 (拡張子なし) と同じ。英小文字と数字と `_` だけ |
| `name` | 会社の名前 (問 1) |
| `industry` | 業種 (問 1) |
| `item_fields` | 部品マスターに足す項目の並び (問 2)。1 つの項目は `label`・`type`・`required`・`in_list`・`searchable` を持つ |
| `settings` | 選べる設定 5 つと `hidden_fields`。中身がそのまま会社の `settings.py` の `SEIZOU` になる |
| `port` | 開発サーバーのポート |

## 種のファイル

1 社のフォルダに 11〜13 のファイルを置く。2 社とも行が入っている (作り物)。1 社あたり、品目 30・取引先 5・品番の対応 10・工程 5・受注 20 (明細は 1〜3 行)・つながり 1 に、標準の工程・指示書・出荷・納品書・請求書の 5 つのファイルが加わる。

| ファイル | 1 行 (1 件) が持つ物 |
|---|---|
| `items.csv` | 品目。自社品番・品名・図面番号・図面ファイル・単位・標準単価・備考と、その会社の `item_fields` の項目 |
| `partners.csv` | 取引先。取引先コード・名前・略称・取引先の種類 (得意先 / 協力企業 / 両方)・締日・支払の月 (当月 / 翌月 / 翌々月)・支払日 (1〜31。月末は 31)・小計の計算方法・消費税の計算方法・備考 |
| `partner_items.csv` | 取引先ごとの品番。取引先コード・自社品番・取引先の品番・取引先の品名 |
| `processes.yaml` | 工程。工程コード・名前・協力企業に出すか・並び順・計画に使う |
| `accounts.yaml` | 権限の種の印。このファイルがあると部署 4 つとアカウント 3 つ (`genba`・`jimu`・`keiri`) を入れる (中身は読まない。部署とアカウントは `seizou.accounts.demo_seed` に固定) |
| `orders.yaml` | 受注。得意先の取引先コード・受注日・得意先の注文番号・備考と、明細の並び (自社品番・数量・単位・単価・納期・備考) |
| `connections.yaml` | つながり。取引先コード・受け口の URL・鍵の置き場の名前・向き |
| `item_processes.csv` | 部品の標準の工程の並び。自社品番・工程コード・順 (1 行 = 1 品の 1 工程) |
| `workorders.yaml` | 指示書 (工程の予定つき)。得意先の取引先コード・得意先の注文番号・行番号・数量と、工程の並び (工程コード・予定の数・開始日・終了日) |
| `shipments.yaml` | 出荷。得意先の取引先コード・得意先の注文番号・行番号・数量・出荷日・備考 |
| `delivery_notes.yaml` | 納品書。得意先の取引先コードと、入れる出荷の並び (得意先の注文番号・行番号・出荷日) |
| `invoices.yaml` | 請求書。得意先の取引先コード・発行日と、入れる出荷の並び (納品書と同じ形) |
| `stock_moves.yaml` | 在庫の動き。種類 (製造の完了 / 払い出し)・得意先の取引先コード・得意先の注文番号・行番号 (製造の完了のとき。その明細の指示書を入庫にする)・自社品番 (払い出しのとき)・数量・日付・備考 |
| `receipts.yaml` | 受入 (A 社だけ)。協力企業への発注 (取引先コード・発注日・備考・明細の並び) と、その受入の並び (行番号・受入日・数量・備考)。発注は相手に送らずに入れる |
| `files/` | 図面の見本の絵 (A 社だけ)。`items.csv` の図面ファイルの欄が、この中のファイルの名前を指す |

- CSV は BOM 付きの UTF-8 で、1 行目が見出し。見出しは部品の表の日本語の項目名をそのまま使う。
- YAML は、1 つの鍵の下に 1 件ずつの並びを持つ。1 件の形は、ファイルの冒頭のコメントに書いた。
- `[空欄: 何を・いつ決めるか]` の印は、まだ決まっていない値。
- 量は、品目 30・取引先 5・受注 20 (明細は 1〜3 行)・工程 5・品番の対応 10 (2 社とも同じ)。取引先の名前は作り物の造語で、実在かどうかの確かめはしていない。日付は 2026 年 10〜11 月の中。
- 新しい種の量。受注の 1〜10 件目 (受注日の古い 10 件) は、全部の明細を出荷済みにして納品書に入れ、そのうち一部を請求済みにする。11〜20 件目は出荷せず、1 行目の明細に指示書を 1 枚ずつ置く。
  - A 社 (`a_machining/`): 標準の工程 85 行 (30 品の全部に 2〜4 工程)・指示書 10 (工程の予定の日は 11-02〜11-13 の平日。2 枚は日を置かず、盤の未計画の列に出る)・出荷 21 (2 明細は 2 回の分納)・納品書 6・請求書 2 (明細 6 行)・図面 4 (PNG 3 枚と TIFF 1 枚)。
  - B 社 (`b_plating/`): 標準の工程 120 行 (30 品の全部に 4 工程)・指示書 10 (計画に使う工程はめっきだけ。2 枚は日を置かない)・出荷 21 (2 明細は 2 回の分納)・納品書 5・請求書 2 (明細 5 行)・図面は無し (表面処理の品目は図面番号が空)。
  - 在庫の動き (A 社・B 社とも 完成 3・払い出し 1)、受入 (A 社だけ。発注 1 件と受入 2 件。発注は相手に送らない)。
- 図面の見本は、A 社のフォルダの下の `files/` に置いた (PNG 3 枚 `WK-1001.png`・`WK-1004.png`・`WK-1010.png` と、白黒 G4 圧縮の TIFF 1 枚 `WK-1003.tif`。どれも 50 KB 以下の線と英数字だけの絵で、`SAMPLE DRAWING (FICTIONAL)` と書いてある)。`items.csv` の図面ファイルの欄には、`files/` の中のファイルの名前だけを書く。
- まだ作っていない物: 注文書の PDF・壊れた TIFF・壊した CSV (これも `files/` に置く予定)。

## 読み込みの命令との約束

- `seizou new examples/companies/<id>.yaml` が答えの YAML を読み、`~/seizou-sites/<id>/` に会社のプロジェクトを作る。
- `--demo` を付けると、答えの YAML と同じ場所の `examples/companies/<id>/` から種を入れる (読み込みは `seizou.core.demo` の `load(種のフォルダ)`)。種のフォルダが無ければ、日本語の文で止まる。
- 入れる順は、品目 → 取引先 → 品番の対応 → 工程 → 受注 → つながり → 標準の工程 → 図面 → 指示書 → 出荷 → 納品書 → 請求書。入れるときは部品の `services` の関数を通し、表に直接書かない。
- 新しい 6 種類 (標準の工程から請求書まで) のファイルは、無くてもよい。無い種類は「入れた 0・飛ばした 0」で、出力の行も出さない。図面は `files/` のフォルダがあるときだけ入れる。
- 2 回入れても重ならない。自然な鍵で既にある物は飛ばし、上書きしない (品目 = 自社品番、取引先 = 取引先コード、品番の対応 = 取引先 × 取引先の品番、工程 = 工程コード、受注 = 得意先 × 得意先の注文番号、つながり = 取引先 × 向き)。そのため、受注は全部、得意先の注文番号を持つ。種を直して入れ直すときは、置き場を作り直す。
- 新しい 6 種類も、自然な鍵で既にある物は飛ばし、上書きしない (標準の工程 = その部品に並びが 1 行でもある、図面 = その部品に図面が既にある、指示書 = その受注の明細に取消でない指示書が既にある、出荷 = その受注の明細に出荷が既にある、納品書と請求書 = 指した出荷のどれかが、既に発行の納品書か請求書に入っている)。今ある置き場に入れ直すと、足りない物だけが入る。
- 種の受注の明細は、得意先の取引先コード × 得意先の注文番号 × 行番号 で指す (受注番号は会社の連番なので、種に書けない)。出荷は 受注の明細 × 出荷日 で指すので、同じ明細に同じ日の出荷を 2 つ置かない。納品書と請求書は、この形で出荷を指す。見つからないときは、ファイルと「N 件目」を書いて止まる。
- 納品書と指示書の発行日は、部品の `services` が今日にするので、読み込みの日になる (種に書かない)。請求書の発行日は種に書く。出荷の日と工程の予定の日は、2026 年 10 月〜11 月 13 日の固定の日付で、読み込みの日から数えない。
- 読み込みは検査の層 (`seizou.core.checks`) を通らないので、受注より多い出荷と指示書の数量は、種を作る側が置かない (試験が見る)。
- 1 行でも部品の `services` が断ったら、ファイルと位置を書いて止まり、何も入れない (全体が 1 つのトランザクション)。
- 会社ごとの項目 (`items.csv` の見出しのうち部品の表に無い物) は、答えの YAML の `item_fields` の見出しと突き合わせて入れる。
- 鍵の値は種に書かない。つながりが持つのは環境変数の名前だけで、値は 2 社の `.env` に、人が同じ値を置く。A 社が `SEIZOU_PARTNER_B_PLATING_SECRET`、B 社が `SEIZOU_PARTNER_A_MACHINING_SECRET` を持ち、2 つの値は同じにする。
- 2 社のつながり: A 社は B 社 (取引先コード `S001`、協力企業) へ「送る」。受け口は B 社の `http://127.0.0.1:8002/connect/receive/order/`。B 社は A 社 (取引先コード `C001`、得意先) から「受ける」。B 社の `partner_items.csv` は、A 社の品番のまま届く注文を、B 社の自社品番で受けるための対応 (取引先 = A 社、取引先の品番 = A 社の自社品番)。

## 置いてよい物

- 作り物だけを置く。実在の会社名・人名・品番・図面を使わない。
- 鍵の値 (署名に使う秘密の値) とパスワードを書かない。つながりには、鍵の値を入れる環境変数の名前だけを書く。値は会社のプロジェクトの `.env` だけに置く。
