# 決まりと権限

読み手: 会社のシステムを預かる人と、直す開発者。お金と数の決まりを守る仕組みと、アカウントごとの使える範囲を書く。入口は [README](../README.md)。

## 決まり

お金と数の決まりは、番号をつけて [RULES.md](../RULES.md) に日本語で並べ、番号ごとに自動テストのファイル (`tests/test_r<番号>_<短い名前>.py`) を 1 対 1 で結ぶ。R20 だけはテストの代わりに製品の hook (`plugin/hooks/guard_core.py`) が守る。hook の動きは `tests/test_plugin_guard_core.py` が確かめる。お金と数の決まりを破る変更は本番の前に止まる。止める仕組みは 2 つに分かれる。コードの変更は、CI と起動時の決まりの検査と自動テストが、本番に入る前に止める。起動時の決まりの検査が回るのは開発の起動 (`DEBUG=1`) のときで、本番の形 (`DEBUG=0`) の置き場では回らない。本番の点検 `seizou_doctor` が会社の置き場の決まりの検査も回し、違反があれば「直す」の行で知らせる (cron で毎朝回す置き場では、「直す」の行がメールで届く)。会社の置き場には CI が無いので、会社が画面を足したら、開発の起動か `seizou_check` か `seizou_doctor` で違反 0 を確かめてから本番に入れる。動いている間の入力 (出荷の数など) は、`services` と DB の制約がその場で止める。ポカよけは会社ごとに止める・知らせる・通すを選べる ([「選べる設定」](settings.md))。

アカウントごとの使える範囲は、部署・編集の権限・金額の閲覧の 3 つの判定で決める。部署は左のメニューに出る画面と開ける画面を、編集の権限はどの種類のデータを登録・変更・削除できるかを、金額の閲覧は単価と金額が見えるかを決める。3 つとも、会社の設定 `access_control` で `off` (使わない)・`log` (記録だけ)・`on` (有効) を選ぶ。立ち上げてすぐは記録だけにし、断られる人がいないかをサーバーの記録 (`seizou.access` の行) で確かめてから有効にする。その間、本番の点検 (`seizou_doctor`) は「権限の判定」の直す 1 件で終わる (確認を終えたら有効にする合図)。システム管理者とフルコントロールの人は 3 つの制限を受けない。判定は core の 1 か所 (`seizou.core.access`) にあり、画面の土台が呼ぶ。

会社の置き場のコードが決まりに沿っていないと、開発のサーバーのどの画面も「決まりに沿っていません」の 1 枚になる。この画面には違反の番号・文・ファイルと行・直し方と、文を写すボタンが出る。違反の一覧は起動のときに会社の置き場の `.seizou/violations.md` にも写る。`/seizou:fix` が会社の置き場の側だけを直す。
