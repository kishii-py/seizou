# 言葉の一覧

読み手: seizou の文書を初めて読む方。文書に説明なしで出てくる語の意味を、短く並べる。入口は [README](../README.md)。

| 語 | 意味 | 詳しくは |
|---|---|---|
| 部品マスター | 品番・品名・図面など、部品の情報を 1 か所に持つ表と画面。受注・指示書・出荷・請求書・発注・在庫などの画面は、部品マスターの品番を軸につながる | [「背景」](why.md)・[「画面の一覧」](screens.md) |
| 置き場 | 会社ごとのプロジェクトのフォルダ。`seizou new` が作り、既定は `~/seizou-sites/<会社の id>/`。管理の命令は、置き場に移ってから打つ | [「入れて触る」](getting-started.md)・[「運用の手引き」](operations.md) |
| 答えの YAML | 会社の id・名前・ポートと、会社ごとの項目と設定を書いたファイル。`seizou new` が読んで置き場を作る。`/seizou:build` の 3 問の答えも同じ形で書かれる | [「答えの YAML の書き方」](answers.md) |
| 種 | `seizou new --demo` が入れる作り物のデータのファイル。答えの YAML と同じ場所の `<会社の id>/` のフォルダ (種のフォルダ) に置き、部品・取引先・受注などを読み込む | [「入れて触る」](getting-started.md)の触り方 2・[種の説明](../examples/companies/README.md) |
| 業種の見本 | 業種ごとの、部品マスターの項目・工程・向く設定の組。今は機械加工・表面処理・鋳造・板金の 4 本。答えの YAML の `industry` が見本の名前か言い換えに当たると、`seizou new` が最初に入れる | [「答えの YAML の書き方」](answers.md) |
| ポカよけ | 受注より多い出荷のような間違いに気づかせる検査。会社ごとに、止める・知らせる・通すを選べる | [「選べる設定」](settings.md) |
| 決まり | お金と数の決まり。`RULES.md` に R01 のような番号をつけて日本語で並べ、番号ごとに自動テストのファイルを 1 対 1 で結ぶ。ポカよけにも番号がある | [「決まりと権限」](rules.md)・[RULES.md](../RULES.md) |
| つながり | 取引先と注文を送り合うための登録。1 つの取引先に、送る向きと受ける向きの 2 行を登録する。設定の「取引先との接続 (つながり)」で登録する | [「取引先とのつながり」](connect.md) |
| 受け口 | 取引先から送られた注文や返事を受け取る、会社のシステムの窓口の URL。注文は受ける会社の受け口へ、注文回答・出荷の知らせ・検収は発注した会社の受け口へ届く | [「取引先とのつながり」](connect.md) |
| 鍵 | 取引先とやり取りする注文のデータに付ける署名の秘密の値。両方の会社の `.env` に同じ値を置き、名前は `SEIZOU_PARTNER_<相手の会社の id を大文字にした物>_SECRET` にする。注文書の読み取りと AI チャットの文では、Anthropic の API の鍵 (`ANTHROPIC_API_KEY`) も「鍵」と呼ぶ。答えの YAML と設定の表の「鍵」は、値に付けた名前のこと | [「取引先とのつながり」](connect.md)・[「入れて触る」](getting-started.md)の前提 |
| 受信した注文 | 取引先 (seizou どうし) から受信した注文のデータと、それを並べる画面。人が「受け入れる」を押すまで受注にならない | [「画面の一覧」](screens.md) |
| 協力企業 | 仕事を出す先の取引先。取引先の種類は得意先・協力企業・両方から選ぶ。協力企業へは「発注」の画面で発注し、つながりのある相手へは同時に注文を送る | [「画面の一覧」](screens.md) |
| 控え | データベースと上げたファイルのバックアップ。置き場で `<python> manage.py seizou_backup` を打って取る | [「運用の手引き」](operations.md) |
| 戻し | 控えから元に戻すこと (復元)。今のデータベースと上げたファイルが、控えを取った時点の物に置き換わる。命令は `seizou_restore` | [「運用の手引き」](operations.md) |
| 点検 | 置き場の立ち上げの確かめ。命令は `seizou_doctor` で、読むだけで何も書き換えない。直す物があれば「直す」の行で知らせる | [「運用の手引き」](operations.md) |
| 練習モード | 今のデータの写しを使う練習用のサーバー。置き場で `manage.py seizou_practice start` を打つと別のポートで起動する (SQLite の置き場だけ)。ここでの登録は本番に残らず、取引先へも送らない | [「画面の一覧」](screens.md)の練習モード・[「運用の手引き」](operations.md) |
| 本番 | 社内で実際に使う置き場。本番の形では `.env` の `DEBUG` を 0 にする (`seizou new` の既定は開発の設定の 1)。本番で使うときの決まりと点検は別の文書にある | [「本番で使う」](production.md) |
| 世話役 | seizou の OSS の側で、Issue と PR を受け付け、merge する役。今は作者が暫定で務める。会社の中でフィードバックを確かめて GitHub に送る人は、アカウント管理の担当者と呼ぶ | [GOVERNANCE.md](../GOVERNANCE.md) |
