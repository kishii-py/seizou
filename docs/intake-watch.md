# 注文書の見張り (フォルダに置いた注文書を読み取り、届いた注文に並べる)

読み手は、会社のシステムを預かる人です。プログラムは書けなくてかまいません。

## この文書は何か

この文書は、紙・FAX・PDF の注文書を、複合機のスキャン先や共有フォルダに置くだけで「届いた注文」の画面に並べる仕組み (注文書の見張り) の立て方と止め方です。

見張りの命令は、フォルダに置いた注文書を古い順に 1 枚ずつ Claude に読ませます。読み取った中身は「届いた注文」の一覧に、入口「読み取り」の行で並びます。人が詳細で中身を確かめて「承認」を押すまで、受注にはなりません。

命令は、置き場 (`seizou new` が作ったフォルダ) に移ってから、`<python> manage.py …` の形で打ちます。`<python>` は、置き場の README の「起動」の 1 行に出てくる Python と同じ物です。

## 用意する物

- 鍵: 置き場の `.env` に `ANTHROPIC_API_KEY` の 1 行を置きます。画面の「注文書を読み取る」と同じ鍵です。鍵の値は画面にも命令の出力にも出ません。
- 見張るフォルダ: 複合機のスキャン先か共有フォルダです。置き場の PC から読み書きできる道にします (例 `~/seizou-scan`)。
- 読み取った人にする利用者: 命令は、届いた注文と読み取りの記録に「読み取った人」を残します。既定はログイン ID `admin` (`seizou new` が作る管理者) です。

## 立て方

置き場で次の命令を打ちます。見張りは止めるまで動き続けます。

```
<python> manage.py seizou_intake_watch <フォルダ>
```

命令は「見張りを始めました: <フォルダ> (10 秒ごと。…)」を出し、10 秒ごとにフォルダを見ます。注文書を 1 枚読むたびに、次の形の 1 行を出します。

- `読んだ: <ファイルの名前> → 届いた注文 <番号> (取引先 <名前>)`
- `読んだ: <ファイルの名前> → 届いた注文 <番号> (差出人の確認待ち: <読み取った差出人>)`
- `同じ中身: <ファイルの名前> → 届いた注文 <番号> に入っています`
- `読めなかった: <ファイルの名前> → failed/<名前> (<理由>)`

見回りの間は `--interval <秒>` で変えます (1 以上)。読み取った人を変えるときは `--user <ログイン ID>` を付けます。

見張るフォルダは、会社の答えの YAML の `settings` に 1 行書いておくと、命令の引数を省けます。

```yaml
settings:
  intake_watch_folder: ~/seizou-scan
```

常駐させずに、cron で決まった時刻に 1 周だけ見る形もあります。`--once` は 1 周だけ見て、`1 周見ました: 読んだ <a> 件・同じ中身 <b> 件・読めなかった <c> 件` を出して終わります。

```
*/5 * * * * cd <置き場> && <python> manage.py seizou_intake_watch --once >> intake-watch.log 2>&1
```

見張りは、1 つの置き場に 1 本だけ立てます。動いている見張りがあると、2 本目の常駐と `--once` は「既に見張っています」で断られます (2 本が同じファイルを読まないように)。

## 止め方と、動いているかの見方

止めるときは、次の命令で止める合図を置きます。見張りは次の見回り (`--interval` の秒以内) で止まり、「見張りを止めました」を出します。命令を打った画面で Ctrl+C を押しても止まります。

```
<python> manage.py seizou_intake_watch --stop
```

動いているかは `--status` で見ます。答えは次の 3 つです。

- `見張りは動いていません。`
- `動いている: <フォルダ> (pid <番号>・<秒> 秒ごと・始めた日時 …・最後の見回り …)`
- `止まっている (記録が古い): <フォルダ> (…)。もう一度立てると置き直します。` (PC の再起動などで、見張りが止めの手順を通らずに止まったときの答えです。もう一度立てれば、そのまま動きます)

見張りの記録は、置き場の `intake_watch.json` に 1 本だけ置きます。止めると消えます。

## 読んだ後のファイル

- 読んだ注文書は、見張るフォルダの中の `done/` へ動きます。
- 読めなかった注文書は `failed/` へ動き、同じ名前に `.txt` を付けたファイル (例 `failed/order.pdf.txt`) に理由が 1 行で入ります。理由を直してから (鍵を置く・PDF で読み込み直す など)、`failed/` のファイルを見張るフォルダに戻すと、もう一度読みます。
- 同じ名前のファイルが `done/` や `failed/` に既にあるときは、`order-2.pdf`・`order-3.pdf` のように番号を付けて動かします。
- 同じ中身の注文書は、2 回置いても届いた注文は 1 行です (FAX の送り直しなど)。2 回目は Claude に読ませずに `done/` へ動き、「同じ中身」と出ます。
- 書きかけのファイルは読みません。最後に書いてから 2 秒たったファイルだけを読みます (複合機や共有フォルダへの写しが終わるのを待つため)。
- 見るのはフォルダの直下の PDF・PNG・JPEG (拡張子 `.pdf`・`.png`・`.jpg`・`.jpeg`) だけです。ほかのファイルとフォルダは動かしません。

## 届いた注文での扱い

- 見張りが入れた行は、届いた注文の一覧の列「入口」が「読み取り」になります。seizou どうしの受け口から届いた行は「直接」です。
- 命令は、注文書から読んだ差出人の会社名を、取引先 (種類が得意先か両方) に当てます。当て方は、名前の完全一致 → 空白と全角半角と大文字小文字をそろえた名前の一致 → そろえた略称の一致の順です。
- 当たらないか、2 つ以上に当たった行は、取引先の欄が黄の「差出人の確認待ち」になります。詳細の「差出人を選ぶ」で得意先を選ぶと、「承認」を押せるようになります。名前を当て違えた行も、承認の前なら同じ所で選び直せます。差出人を選べるのは、承認できる人だけです。
- 承認すると受注ができ、受注の入口は「読み取り」になります。注文書に単価の無い明細は、部品マスターの標準単価にします。標準単価も無いときは承認が断られるので、部品マスターに標準単価を入れてから承認します。注文書に注文日が無ければ、届いた日を注文日にします。
- 見張りの行は、相手の seizou とつながっていないので、承認しても断っても注文回答を送りません。その受注を出荷しても、出荷の知らせを送りません。
- 同じ取引先から同じ注文番号の注文が 2 つ目として届くと、一覧と詳細に黄の「同じ注文番号の注文が既に届いています」が出ます。断りはしないので、前の行と見比べて決めます。

## 注意

- 鍵が無いまま見張ると、置いた注文書は全部 `failed/` へ動きます (理由は「鍵が無いので読み取りは使えません。…」)。命令は始める時に、鍵が無いことを 1 行で知らせます。鍵を置いてから、`failed/` のファイルをフォルダに戻してください。
- 注文書 1 枚ごとに Claude の API を呼びます (費用がかかります)。API が混んでいる・時間切れのときも、繰り返し呼ばずに `failed/` へ動かします。少し待ってからフォルダに戻してください。
- 読み取った値は AI が読んだ物です。承認の前に、詳細の明細を注文書と見比べてください。
- 読めるのは PDF・PNG・JPEG の 20MB までです。
- 画面の「注文書を読み取る」(得意先を選んでファイルを置く) は今までどおりで、届いた注文を通らずに、読み取りの画面の「受注にする」で受注にします。見張りが読んだ注文書は、読み取りの一覧にも「届いた注文へ回した」で並びますが、そこからは受注にできません (1 枚の注文書から受注を 2 つ作らないため)。
