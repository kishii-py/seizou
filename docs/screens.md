# 画面の一覧と業務の流れ

読み手: 使う会社の方。どの画面で何ができるかと、受注から請求までの流れを書く。入口は [README](../README.md)。

## 画面の一覧

左のメニューの入口ごとの一覧。大項目と入口の名前は、画面の左のメニューと同じ (大項目は開け閉めでき、今の画面の大項目だけ開く。製造業なので製造部をダッシュボードのすぐ下に置く)。画面の言葉は新規登録・編集・保存・キャンセル・一覧に戻る・詳細を見る・検索・絞り込み・ダッシュボード・マニュアルにそろえている。画面の題の下に説明の文は出さず、題の横の「?」で説明書の断片を開く。

左のメニューには、表の入口のほかに、下の「フィードバック」(困りごと・要望・不具合を伝える。下の「フィードバック」の節) と、上の帯の ☆ で登録した画面が登録の順に並ぶ組「ブックマーク」がある。

右上の利用者のメニューの「設定」から、会社の選べる設定の今の値と出所 (アカウント管理の権限がある人は編集もできる。[「選べる設定」](settings.md))・取引先との接続 (つながり)・添付ファイルの一覧 (整理用。付けるのは各詳細の「添付ファイル」の枠から)・アカウント管理 (権限の Django の部品が入っている会社)・フィードバックの一覧 (フィードバックの Django の部品が入っている会社)・システムの状態 (アカウント管理の担当者は「点検を走らせる」で、命令 `seizou_doctor` と同じ点検の直す物を最初の 3 件まで見る) を開く。同じメニューの「表示の設定」で、上の帯の色を 8 つの見本から選べる (自分の画面だけに効き、共用の端末でほかの人のアカウントのまま触り続ける事故に目で気づける)。普段は触らない物は左のメニューに置かない。上の帯にはどの画面でも ☆ (今の画面を「よく使う画面」に登録する。押すと小窓に登録した画面の一覧と「消す」が出る)・鈴 (受信した注文と自分のフィードバックの動きのうち、まだ見ていない物の数。押すと新しい順に並ぶ)・「案内」(その画面の使う人・いつ・何のために・次にすること)・「使い方」のボタン (画面ごとの説明書)・横断の検索 (「品番・品名・注文番号で検索」) がある。右下の丸いボタン (AI に質問) を押すと、AI チャットの窓が右下に開く (鍵のある会社だけ。[「前提」](getting-started.md)と下の「AI チャット」)。全部の画面の名前と 1 文は `uv run python -m django seizou_screens --settings=tests.settings` で出る。会社の置き場では、使い方の目次が同じ順に並ぶ。

## 業務の流れ

受注は手で入れるか、受信した注文を受け入れるか、注文書の読み取りから作る。受注の明細から指示書を発行すると、部品の標準の工程か選んだ工程の並びが指示書に写る (取消した受注には、出荷も指示書も作れない。R05)。進捗は工程ごとに実績を入れる所で、進捗の盤は開いたまま 10 秒ごとに、新しい実績が入った行を差し替える。出荷は受注の明細ごとに入れ、分納と、受注より多い出荷 (R01) は会社の設定に従う。納品書は同じ得意先の出荷を 1 枚にまとめ (数量は出荷と一致する。R08)、印刷用の画面と PDF を開ける。請求書に入れられるのは、発行した納品書に入った出荷だけ (R09)。支払期日は取引先の締日と支払の月と支払日から決まり、消費税の率は今は 1 つ。協力企業への発注は保存と同時に注文を送る。A 社から B 社へ送った注文は B 社の受信した注文に届き、人が受け入れるまで受注にならない (R10)。

### 生産計画

工程ごとに日を横に並べた計画の盤 (ガントチャートのような表)。右の「未計画」から日へドラッグして指示書の工程を置き、棒を押すと指示書を小窓で開く。使うかは設定 `production_plan` で選び、工程の画面で「計画に使う」に印を付けた工程ごとに盤が並ぶ。盤の上には月・日・曜日の 3 段の見出しと今日の印があり、横にスクロールしても左の列の見出しは動かない。棒は部品ごとの色で塗り、枠の線の色で状態 (計画・着手・完了・遅れ) を分ける。棒に触れると、吹き出しに指示書番号・部品・数量・納期・日・状態・前後の工程が出る。凡例 (状態・部品の色・休日・今日) は盤の上にある。

### 注文書の読み取り

注文書の PDF・PNG・JPEG (20MB まで) を AI (Claude の API) が読み、明細を取り出す。人が中身を確認し、自社の部品を選んで「受注登録」を押すまで、受注にはならない。鍵と費用は[「前提」](getting-started.md)の表に書いた。使う model は会社の `settings.py` の `SEIZOU["intake_model"]` で替えられる。

### 使い方

上の帯の「使い方」を押すと、画面の目録の順 (部品と URL の並び) に並んだ目次と、画面ごとの説明が開く。説明は会社の置き場の `manual/` の断片で、`/seizou:manual` が書く。断片の無い画面には、無い旨の案内が出る。印刷用の 1 枚の画面もある。説明書は PDF の冊子にもなる。冊子と使い方の画面と印刷用の 1 枚には、画面ごとの章の前に業務の流れの章 (注文を受けてから入金まで・発注から受入まで・取引先とつなぐ) が付き、手順の画面の名前からその画面の章へ飛べる。「使い方」の画面の「PDF」(`/manual/pdf/`。表紙・目次・画面ごとの章・ページ番号) で開くか、会社の置き場で `manage.py seizou_manual_pdf` を打つと `manual/使い方.pdf` に書き出す (`--out` で場所を変えられる)。画面の題の横の「?」を押すと、その画面の説明書の断片が小窓で開く。ダッシュボードの枠と詳細の枠にも「?」があり、押すとその枠の説明だけが出る。
断片と同じ名前の絵 (`manual/images/<断片の名前>.png`) があれば、断片に `<img>` が無くても絵が付き、入力の画面には「入れる物」の表 (欄の名前・必須・説明) が、部品ごとには「止まるときの文」(保存や取消を断るときの文) が自動で入る。絵は手元で会社を動かしたまま会社の置き場で `manage.py seizou_manual_shots` (Playwright が要る) を打つと、全部の画面をまとめて撮れる。既定は窓 (幅 1280・高さ 800) の最初の 1 画面で、`--full-page` を付けたときだけ画面の全体を撮る (使い方の画面そのものは撮らない)。冊子では絵の高さを 200mm までに収める。

`seizou new` は、画面ごとの説明書の断片の標準の組 (部品の中の `src/seizou/core/manual_default/`) を置き場の `manual/` に写す。会社ごとに直すなら、置き場の `manual/` のそのファイルを編集するか、`/seizou:manual` で書き直す。`--demo` で立てた 2 社は種の断片 (`examples/companies/<id>/manual/`) を先に写すので、同じ名前は種の断片が勝つ。

### 練習モード

会社の置き場で `manage.py seizou_practice start` を打つと、今のデータの写しを使う練習用のサーバーが別のポートで起動する (SQLite の置き場だけ)。全部の画面の上に黄色の帯「練習モード」が出て、ここでの登録は本番に残らず、取引先へも送らない。`seizou_practice stop` で止めると写しも消える。手順と注意は `docs/operations.md` の「練習モード」にある。

### 今日やることと案内

ダッシュボードの数字のカードの下の枠「今日やること」には、受注から入金までと発注から検収までの流れのうち、人の作業が残っている段階が「<何を> n 件」と移る先のボタンで並ぶ。ボタンを押すと、その物を扱う画面が開く (絞りのある一覧は絞りの入った形で、納品書と請求書はその出荷だけが並ぶ作る画面)。人の作業が 1 つも残っていないときは、「はじめての方へ」として流れの段の並びが出る (部品も取引先もまだ無い会社には、その上に「最初にすること」= 取引先を登録する → 部品を登録する → 受注を入れる のボタンが並ぶ)。上の帯の「案内」を押すと、その画面の使う人・いつ・何のために・次にすることと流れの前後の画面が小窓で開き、ダッシュボード・受注の一覧・生産管理ボードでは「順に見る」で画面の要素を順に示す。

### AI チャット

画面の右下の丸いボタン (吹き出しの絵。読み上げの名前は「AI に質問」) で開く窓 (鍵のある会社だけ。[「前提」](getting-started.md))。今の画面の使い方・部品・受注の残・指示書・出荷・業務マニュアルを質問できる。読む道具は MCP と同じ物で、答えの下に使った道具の名前が並ぶ。受注の登録・出荷・計画の置き直しは、AI が保存せず「提案のカード」になる。人が「承認」を押すと、画面と同じ決まりとポカよけを通って保存される (知らせる設定に当たると、知らせと「このまま保存」のボタンが出る)。

### フィードバック

左のメニューの下の「フィードバック」から、現場の人が困りごと・要望・不具合を伝える。入力の形は種類 (不具合 / 決まりの反例 / 決まりの提案 / 業務の流れの違い / 要望 / 使い方)・画面 (開いていた画面が初期値)・題・困りごと・場面・望む形・影響する画面。鍵のある会社では、AI の聞き取りのカード (広い幅では入力の形の左、狭い幅では上) が 1 問ずつ (最大 4 問) 聞き取り、画面を移らずに下書きを入力の形へ入れる (AI が読むのは画面の目録・画面ごとの説明書・会社の設定だけで、コードと受注や部品のデータは読まない。使い方の問いには説明書で答えてその場で終わる)。下書きは会社の中に残り、一覧 (誰でも自分の分を、アカウント管理の権限がある人は全員の分を見られる) と詳細で見る。詳細の「Issue の文」は GitHub の Issue に写す文で、取引先の名前と金額らしい数は「〇〇」に伏せてある。世話役が見て「確認済み」にする。トークンが無い会社は、世話役が GitHub に手で写してから「送った」にする (トークンのある会社は下の段落)。会話ごとに使った token は一覧に出る。使う model は設定 `feedback_model` (既定は安い haiku)。

下書きのうちは、書いた人とアカウント管理の担当者が、詳細の「削除」で消せる (確認済みと送った物は消せない)。一覧は状態と種類で絞り込める。編集の画面を開けるのは、その下書きが一覧に出る人 (書いた人とアカウント管理の担当者) だけ。

入力の形 (新規登録と編集) の「画面の絵」の欄に、困った画面の絵 (PNG・JPEG・WebP) を 1 枚 5MB まで、1 回に 3 枚まで付けられる (欄へドラッグしても入る)。絵は添付ファイルとして下書きに付き、詳細の「画面の絵」に小さく並ぶ (押すと開く)。Issue の文の末尾には枚数とファイル名だけが入り、絵は世話役が GitHub の Issue に手で付ける。AI の聞き取りが下書きを作ったときの知らせにも、画面の絵の欄の案内が出る。

GitHub とつなぐ: アカウント管理の権限がある人は一覧の「GitHub の設定」から画面「GitHub とつなぐ」を開き、画面の手順のとおりに GitHub でトークン (classic。権限は `public_repo` だけ。非公開のリポジトリへ送るなら `repo`) を作って貼る。会社の人の個人の GitHub のアカウントでなく、フィードバック専用のアカウントを勧める。トークンは会社の置き場の `.env` にだけ置き、画面にも記録にも二度と出ない。つないだ会社では、確認済みの物だけを詳細の「GitHub に送る」で Issue にでき、Issue の URL が詳細に残る。GitHub で Issue が閉じたら、一覧の「GitHub の状態を取り込む」(cron なら `<python> manage.py seizou_feedback_sync`) で「直した」になり、書いた人の次のログインで知らせが出る。送り先の既定は seizou の公開のリポジトリ (`kishii-py/seizou`) で、画面で変えられる。画面の process が `.env` に書けない置き場では、置き場の持ち主が端末で `seizou github-token <置き場>` を打つ。一覧の下の「GitHub の Issue を探す」は誰でも使え、トークンが無くても、似た困りごとが既に出ていないか、送った要望がどうなったかを探せる。seizou の Client ID が入った置き場では「GitHub でログインしてつなぐ」のボタンで、GitHub の画面に 8 文字の符号を打つだけでつながる (OAuth のデバイスの認証。戻り先の URL も client secret も要らない)。

### 業務マニュアル

左のメニューの「マニュアル」は会社の仕事の手順を書き残す業務マニュアル。フォルダの階層で分け、Markdown で書く (ステップ形式とページ形式。画像も入れられる)。保存のたびに版が残り、版の差分を見て前の版に戻せる。保護した物は移動と削除ができない。部品と取引先に紐付けると、その詳細からも開ける。横断の検索と PDF にも対応する。作り物の 2 社には、`--demo` が見本のマニュアルを入れる。

### 図面と添付ファイル

部品の図面は詳細の図面ビューアで拡大・移動・回転・ページ送りをして見る。図面を差し替えると版が残り、版を見比べて前の版に戻せる。受注や部品などの詳細の下の「添付ファイル」の枠には、写真や検査成績書などを付けられる。図面と添付のファイルは、ログインした人にだけ返す。

### 現品票とラベルの QR

指示書の詳細から現品票を、出荷の詳細からラベルを、印刷用の画面と PDF で出す。納品書にも QR が付く。現品票の QR をスマホで読むと、その指示書の工程が並ぶ画面が開き、工程を選ぶとその工程の実績の新規登録へ移れる (記録の後はこの画面に戻る)。

### CSV の取り込み

部品マスターと取引先の一覧にある「CSV 取り込み」から、CSV のファイルをまとめて登録する。見出しは、画面の「見本の CSV をダウンロード」で取れる見本と同じ。同じ自社品番か取引先コードの行は更新する。1 行でも誤りがあれば 1 件も入れず、行・欄・理由の表を出す。読める文字コードは UTF-8 (BOM あり・なし) と Shift_JIS (Excel の既定)。

### 在庫と受入

協力企業への発注 → 受入 (受け入れた数 × 発注の単価が支払の金額) → 在庫、の順につながる。在庫は完成品の在庫で、在庫数は入庫 (製造の完了と受入) の合計から出庫 (出荷と払い出し) の合計を引いた数。出荷は在庫の動きに書かず、出荷の記録から集計で引く。動きの無い部品は在庫を数えていない扱いで、棚卸しの調整で実地の数を入れると数え始める。マイナスの在庫は止めずに赤の数で出す。生産管理ボードには「在庫」の列があり、完成の数か在庫が残以上なら判断が「出荷できる」になる。ダッシュボードには「今月の支払の見込み」のカードが出る。
