# 入れて触る (前提と触り方)

読み手: seizou を初めて触る方。手元の PC に作り物の 2 社を立てて、画面で通す所までと、自分の会社の置き場を立てる最初の手を書く。入口は [README](../README.md)。

## 前提

触る前に要る物と、どこまで確かめてあるか。

| 項目 | 要るか・状態 |
|---|---|
| Claude Code の契約 | プラグイン (立ち上げの命令 `/seizou:build`) で立てるときは要る。下の「触り方」の Python の命令 `seizou new` で立てるときは要らない |
| 外のネット | 最初に入れるときだけ要る (uv と Python の依存を取る)。CSS を作り直す道具 (Tailwind CSS と daisyUI) は、開発のときだけ取る。画面の CSS と JS とフォントは配布物に同梱していて、動かすときに外へ取りに行かない |
| OS | 作者の手元は macOS。Linux と Windows は、試験と、入れる所から画面が開くまでを CI (GitHub Actions) で通している。人の手で通した確認と、日本語の Windows の実機での確認はまだ無い |
| 端末の道具 | `git` と `uv` (Python の道具) が要る。git は git-scm.com の配布物で入る。uv は公式の版つきの 1 行で入る (OS ごとの命令は表の下の「uv の入れ方」)。`/seizou:build` は uv が無ければ自分で入れる |
| 費用 | ソフトは無料 (Apache-2.0)。かかるのは、Claude Code の契約 (プラグインで立てるときだけ)・注文書の読み取りと AI チャットの API の費用 (読んだ分だけ。読み取り 1 枚の実測は下の行)・置き場を VPS に置くならその月額 (手元の PC でも動く) |

| AI チャット | 使う会社だけ、注文書の読み取りと同じ鍵 (環境変数 `ANTHROPIC_API_KEY`) が要る。鍵が無い会社では、右下の丸いボタン (AI に質問) で開く窓に、AI チャットの説明と、使えないことを知らせる字 (「AI チャットは、管理者が設定すると使えます。」と、できることの一覧。アカウント管理の権限がある人には、鍵の置き場を知らせる「AI チャットを使うには、会社の .env に ANTHROPIC_API_KEY を設定します。」も) だけが出て、入力の欄は出ない。質問と、画面の説明書と、道具の結果 (部品・受注・指示書・出荷・業務マニュアルの中身。単価と金額を含む) を Anthropic の API へ送り、読んだ分だけ費用がかかる。答えは誤りうるので、数は答えの link の先の画面で確かめる (SECURITY.md)。受注の登録・出荷・計画の置き直しは、AI が保存せず提案のカードになり、人が「承認」を押してから保存される |
| フィードバックの AI の聞き取り | 使う会社だけ、AI チャットと同じ鍵 (環境変数 `ANTHROPIC_API_KEY`) が要る。鍵が無い会社では、フィードバックの入力の画面に AI の聞き取りのカードが出ず、入力の形だけで伝える。利用者が書いた字と、画面の目録・画面ごとの説明書・会社の設定 (会社の名前・選べる設定の今の値・入っている Django の部品) を Anthropic の API へ送り、読んだ分だけ費用がかかる (使う model は設定 `feedback_model`。既定は安い haiku)。受注・部品・出荷のデータを読む道具と、書く道具は渡さない。下書きは会社の中に残る。GitHub に送るのは、アカウント管理の権限がある人がトークンを置いた会社で「GitHub に送る」を押した確認済みの物だけ ([「フィードバック」](screens.md)) |
| 所要時間 | 1 社なら、インストールから動き出すまで 50.6 秒 = 約 50 秒 (11-08 07:40 ごろ。作者の Mac。uv のキャッシュを空にして測った = `git clone` 32 秒・`uv sync --locked` 7 秒・`seizou new … --demo` 11 秒・runserver を起動して /health/ が 200 になるまで 1 秒。`seizou new` で立てる方法の値で、`/seizou:build` の 3 問に答える時間は入っていない。Claude Code のプラグインで立てる方法は 2 分 54 秒 = 入れる 34 秒 + 3 問に答えて画面が開くまで 140 秒。11-08 12:30 ごろ、uv の cache あり)。2 社なら 49 秒 (11-08 04:20 ごろ。同じ条件 = `git clone` 24 秒・`uv sync --locked` 5 秒 (依存を取る。Python 3.12 は入れてある)・`seizou new … --demo` を 2 回で 19 秒・runserver を起動して /health/ が 200 になるまで 1 秒。外のネットの速さで変わる) |

### uv の入れ方

公式の版つきの 1 行で入れる。版は `/seizou:build` が入れる版と同じ。

macOS と Linux (端末):

```sh
curl -LsSf https://astral.sh/uv/0.13.5/install.sh | sh
```

Windows (PowerShell):

```powershell
powershell -ExecutionPolicy ByPass -c "irm https://astral.sh/uv/0.13.5/install.ps1 | iex"
```

入れた後は、端末の窓を閉じて開き直す (開き直した窓で uv が見つかる)。会社の proxy (社内と外のネットの間の中継) を通るときは、uv の命令の頭に環境変数 `UV_SYSTEM_CERTS=true` を付ける (例 `UV_SYSTEM_CERTS=true uv sync --locked`。uv が PC の証明書を使う)。PowerShell では、uv の命令の前に、同じ窓で `$env:UV_SYSTEM_CERTS = "true"` を打つ。Windows の命令は実機で未確認。

## 触り方

今ある入れ方は、端末で命令を打つ方法だけで、作者の手元 (macOS) で通した物。Linux と Windows は、入れる所から画面が開くまでを CI で通している (人の手で通した確認と、日本語の Windows の実機での確認はまだ無い)。PDF の帳票には WeasyPrint と OS の pango が要る (無くても画面は動く)。

端末の開き方は、Mac は「ターミナル」、Windows は PowerShell、Linux は端末のアプリ。

初めて触る方に向けた、Claude Code を使わない方法。2 社の会社のプロジェクトを作って作り物のデータを入れ、起動してログインし、受注から出荷と納品書までと、A 社から B 社へ注文を送る流れを画面で通せる。鍵 (`ANTHROPIC_API_KEY`) が無くても、注文書の読み取りと AI チャットとフィードバックの AI の聞き取り以外の全部の画面が動く。鍵のある会社でも、AI は受注の登録や出荷を勝手に保存せず、人が提案のカードの「承認」を押すまで保存しない。

1. 入れる (版 v0.1.0 の tag から)。macOS と Linux の端末では、次の 1 行を打つ。

   ```sh
   git clone --branch v0.1.0 https://github.com/kishii-py/seizou.git && cd seizou && uv sync --locked
   ```

   Windows PowerShell 5.1 では、`&&` で命令をつなぐと構文の誤りになる。次の 3 行を 1 行ずつ打つ (実機で未確認)。

   ```powershell
   git clone --branch v0.1.0 https://github.com/kishii-py/seizou.git
   cd seizou
   uv sync --locked
   ```

   帳票の PDF も使うなら、`uv sync --locked` の代わりに `uv sync --locked --extra pdf` を打つ。PyPI の `pip install seizou` でも部品は入るが、例の 2 社の答えと種 (`examples/companies/`) は clone した物を使う。
2. 会社のプロジェクトを作る命令を、`examples/companies/` にある 2 社の答えの YAML で 1 回ずつ打つ: `uv run seizou new examples/companies/a_machining.yaml --demo` と `uv run seizou new examples/companies/b_plating.yaml --demo`。この命令が会社のプロジェクトを `~/seizou-sites/<会社の id>/` に作り、データベースを用意し (migrate)、管理者を 1 人作る。置き場の親は環境変数 `SEIZOU_SITES_DIR` で変えられる。`--demo` は作り物のデータを入れる指定だ。答えの YAML と同じ場所の `<会社の id>/` (種のフォルダ) から、部品・取引先・部品の取引先・工程・受注・つながりと、標準の工程・図面・指示書・出荷・納品書・請求書と、部品が持つ種 (業務マニュアル・権限 (作り物の部署とアカウント)・在庫・出荷の知らせと検収・入金) を読み込む。読み込んだ種類ごとに「<種類>: 入れた n 件・飛ばした m 件」の行を出し、最後に「作り物のデータを登録しました: <種のフォルダ>」の文を出す。種の中身は `examples/companies/README.md` に書いてある。
   答えの YAML の `industry` が業種の見本 (`src/seizou/recipes/` の 4 本 = 機械加工・表面処理・鋳造・板金) の名前か言い換えに当たると、`seizou new` は部品マスターの項目・工程・向く設定を見本から最初に入れ、「業種の見本 (<業種>) から入れました: …」の行を出す (答えの YAML に書いた項目と設定が勝つ。見本を入れないときは答えの YAML に `recipe: none` と書く)。例の 2 社の答えと種は見本と同じ中身なので、足される物は無い。
   答えの YAML に `logo:` (答えの YAML のあるフォルダから見た相対のパスで、PNG か JPEG の絵のファイル) を書くと、`seizou new` は会社のロゴと、ロゴから作った印 (favicon。ブラウザのタブに出る絵) も入れる。後から設定の画面の「会社の情報」でロゴを上げても、印ができる。印は会社の置き場で `manage.py seizou_company_icons` を打つと、ロゴから作り直せる (データベースの表には書かない)。
3. 2 社を別のポートで起動する。A 社 (若葉精機。作り物の名前で、機械加工の注文を送る側) は 8001、B 社 (白樺めっき工業。作り物の名前で、表面処理の注文を受ける側) は 8002。`seizou new` は終わりに「次にすること: <起動の 1 行> で起動し、http://127.0.0.1:<ポート>/login/ を開いてログインします。」の文を出す。「次にすること: 」の後ろから「 で起動し」の前までが起動の 1 行で、置き場と Python の場所が埋めてある。その 1 行を写して端末で打つ。A 社の例は次の形。

   ```sh
   cd ~/seizou-sites/a_machining && <seizou を clone した場所>/.venv/bin/python manage.py runserver 8001
   ```

   この端末は、起動している間ふさがる。B 社は新しい端末の窓を開いて、B 社の起動の 1 行 (末尾が `runserver 8002`) を打つ。止めるときは、その端末で Control を押しながら C を押す (Windows も同じ)。

   Windows の PowerShell では、`seizou new` が出した起動の 1 行が `&&` でつないだ形なら、`cd …` と `& "<python>" manage.py runserver <ポート>` の 2 行に分けて打つ (実機で未確認)。A 社の例は次の形。

   ```powershell
   cd $HOME\seizou-sites\a_machining
   & "<seizou を clone した場所>\.venv\Scripts\python.exe" manage.py runserver 8001
   ```

   この後に出る `<python>` は、起動の 1 行の cd の後ろにある python のパス。macOS と Linux の例は `<seizou を clone した場所>/.venv/bin/python`、Windows の例は `<seizou を clone した場所>\.venv\Scripts\python.exe`。`<python> manage.py …` の命令は、会社の置き場のフォルダ (起動の 1 行の cd の先) で打ち、`<python>` は `<` と `>` ごと python のパスに置き換える。PowerShell では `& "<python>" manage.py …` の形で打つ。
4. ブラウザで http://127.0.0.1:8001/ と http://127.0.0.1:8002/ を開く。2 社は同じブラウザで開いたままにできる (cookie の名前を会社ごとに分けている)。
   1. 開発の設定 (`.env` の `DEBUG=1` と `SEIZOU_DEV_AUTO_LOGIN=1`。`seizou new` の既定) では、ログインの画面を飛ばして管理者として開く (`/login/` を開いたときだけログインの画面が出る)。ログインするときの ID は `admin`。いつもログインの画面を見るには `SEIZOU_DEV_AUTO_LOGIN` を 0 にする。管理者 `admin` のパスワードは `seizou new` の出力に 1 度だけ出る。管理者のパスワードを変えるには、会社の置き場で `<python> manage.py changepassword admin` を自分の端末で打つ (`/seizou:build` で立てたときは、パスワードを会話に出さずに `~/seizou-<会社の id>-admin.txt` に書くので、自分で開いてログインし、ログインしたらファイルを消す)。
   2. 作り物のアカウントは 3 つで、パスワードは 3 つとも `seizou-demo-1103`。外から開ける置き場では `--demo-password random` を使う (3 人に別々の乱数を作り、`seizou new` の出力に 1 人 1 行で出す)。
   3. `genba` (現場) は部署「製造」の人で、左のメニューには指示書・生産計画・進捗・実績・在庫・部品マスター・取引先・工程・休日・マニュアルが並ぶ (ダッシュボード・検索・使い方・設定・AI チャット・フィードバックは、どの部署でも開ける)。受注・生産管理ボード・受信した注文・出荷・納品書・請求書・発注・受入・入荷の一覧と入力の画面は、「この画面は開けません」の画面 (403) になる。進捗の実績と在庫の動きは入れられるが、伝票とマスターは登録できない。
   4. `jimu` (事務) は出荷の画面で伝票を作れるが、単価と金額は「—」で出て、金額に関わる操作 (受注の登録・変更・取消、発注、納品書、請求書と入金) は入口が出ない (金額を見られない人は金額に関わる操作をしない)。`keiri` (経理) は請求書を作って印刷し、金額を見られる。
5. 見る順は、受注 → 出荷が止まる → 受信した注文。手順は次のとおり (ほかの画面の入口は[「画面の一覧」](screens.md)にある)。
   1. A 社で、ダッシュボードから「受注」を開き、「新規登録」で受注を 1 件入れる (得意先と明細の行を選ぶ)。
   2. 「出荷」の「新規登録」で、その受注の明細に、受注より多い数を入れて保存する。A 社は受注より多い出荷を止める設定なので、赤の知らせが出て保存されない。
   3. B 社 (表面処理) は、入荷 (得意先から届いた預かり品の記録) の無い受注の明細を出荷できない設定 (答えの YAML の `receiving_required: stop`) にしてある。B 社では、1 と同じく受注を 1 件入れた後、出荷の前に入荷を 1 件記録する。左のメニューの「製造部」→「入荷」→「新規登録」を開き、「受注の明細」にその受注の明細を、「部品」に同じ部品を選び (受注の明細を選んでも部品は写らない)、「出所」を「預かり」にし、「数量」を入れて保存する (管理者で入れる。作り物の 3 つのアカウントの部署には、今は入荷の画面が入っていない)。入荷を記録しないまま出荷を保存すると、赤の知らせ「保存できません。この明細には支給品・預かり品の入荷がありません。先に「入荷」で記録してください。」が出て保存されない。入荷を記録した後に、2 と同じく受注より多い数で出荷を保存すると、黄の知らせと「このまま保存」のボタンが出て、押せば現物のとおり保存できる (設定の違いは[「選べる設定」](settings.md))。
   4. 部品の「新規登録」の画面を開くと、会社ごとの項目 (A 社は「材質」と「図面の版」、B 社は「処理の種類」と「膜厚 (μm)」) が並ぶ。
   5. 2 社の間で注文を送り合う前に、2 社の `.env` に同じ値の鍵を置き、2 社を起動し直す。値は A 社の置き場で `<python> manage.py seizou_secret SEIZOU_PARTNER_B_PLATING_SECRET` を自分の端末で打って作る。出力の 1 行目は `SEIZOU_PARTNER_B_PLATING_SECRET=<値>` の形で、写すのはこの 1 行の全部 (続く 2 行は注意の字で、写さない)。その 1 行を A 社の `.env` に足し、同じ値を B 社の `.env` に `SEIZOU_PARTNER_A_MACHINING_SECRET=<値>` の 1 行で足す (値は最初の `=` の後ろの全部で、末尾の `=` も値に入る。名前の決まりは[「取引先とつなぐ」](connect.md))。

      `.env` は会社の置き場のフォルダ (`~/seizou-sites/<会社の id>/`) にある。名前が点で始まるので、macOS の Finder は既定で出さない。開き方は OS ごとに次のとおり。

      - macOS: 置き場のフォルダで `open -e .env` を打つ (テキストエディットで開く)
      - Windows: 置き場のフォルダで `notepad .env` を打つ
      - Linux: 使い慣れた編集の道具で開く

      `.env` は起動のときに読むので、書いた後は 2 社を起動し直す。2 社の端末でそれぞれ Control を押しながら C を押して止め、同じ端末で起動の 1 行をもう 1 度打つ。起動し直す前に A 社で発注を保存したときは、起動し直した後に、その発注の詳細の「再送」を押す。
   6. A 社で「発注」の「新規登録」を保存すると、B 社へ注文が送られる。
   7. B 社の「受信した注文」に新しい行が出るので、行の右の「⋮」を開いた中の「受け入れる」を押す。「注文を受け入れる」の画面で、相手の品番ごとに選んである自社の部品を確かめて保存すると、B 社の受注になる。
6. 続けて、2 社の間の往復とお金の流れを見る。B 社が受け入れると、A 社の発注の状態が「相手が受け入れた」になる (注文回答)。B 社は先に「入荷」で A 社から届いた品物を記録してから出荷する (5 の 3 と同じ手)。B 社がその受注を出荷すると、A 社の発注の詳細の明細の「相手からの出荷の知らせ」の列に出荷が出る。A 社がその出荷の「受入を記録する」で受け入れた数を入れると、A 社の在庫に入り、B 社の受注の明細の「検収」の列に受け入れた数が返る。請求書の詳細の「入金を記録する」で入金を入れると、残と入金の状態が変わる。
7. 一覧の絞り込みの期間の欄の下の「今日・今週・今月・先月」を押すと、始めと終わりが会社の時刻で入り、表がその期間に絞られる (週は月曜から)。上の帯の鈴は、受信した注文と、自分が送ったフィードバックの直した・見送った・返事のうち、まだ見ていない物の数を出し、押すと新しい順に並ぶ (開くと印が消える)。☆ で登録した画面は、上の帯の ☆ の小窓とダッシュボードの「よく使う画面」のほか、左のメニューの「ブックマーク」の組にも登録の順に並ぶ。上の帯の「使い方」は画面ごとの説明書の目次を開き、「PDF」で冊子にする (作り物の 2 社には、画面ごとの説明書が入っている)。画面の右下の丸いボタン (吹き出しの絵。読み上げの名前は「AI に質問」) で開く AI チャットは、鍵 (`ANTHROPIC_API_KEY`) を置いた会社だけで使え、受注の登録や出荷は、提案のカードを人が「承認」してから保存される。左のメニューの[「フィードバック」](screens.md)からは、困りごとや要望を書いて残せる。毎日の控えは会社の置き場で `<python> manage.py seizou_backup` を打って取る ([「毎日の運用」](production.md))。

### 社内のスマホから開く (試す間だけ)

起動の 1 行の runserver は 127.0.0.1 だけで待つので、同じ PC からしか開けない。社内のスマホから開くときは、先に `.env` の `SEIZOU_DEV_AUTO_LOGIN` を 0 にする。1 のままだと、社内のどの端末から開いても、ログインせずに管理者として開く (自動ログインは接続元を見ない。`core/middleware.py` の `DevAutoLoginMiddleware`)。次に、PC の社内の番地 (例 `192.168.x.x`) を `.env` の `ALLOWED_HOSTS=` の行に書く (2 つ以上はカンマで区切る。書かないと 400 になる)。そのうえで、起動の 1 行の末尾の `runserver <ポート>` を `runserver 0.0.0.0:<ポート>` に変えて、起動し直す (置き場で `<python> manage.py runserver 0.0.0.0:<ポート>`)。スマホでは `http://<PC の社内の番地>:<ポート>/` を開いてログインする。

現品票と納品書の QR には、刷った時に開いていた住所が入る。スマホで読むなら、PC でも社内の番地の住所で開いてから刷る。上の帯の「現品票を読む」のカメラは https の住所だけで動くので、http の社内の住所では、スマホのカメラのアプリで QR を読んで開く。

スマホの実機では未確認。

## 自分の会社で使い始める

作り物の 2 社で試した後に、自分の会社の置き場を立てる手。

### 自分の会社の答えの YAML

`seizou new` は、答えの YAML (会社の id・名前・ポートと、会社ごとの項目と設定を書いたファイル) から置き場を作る。いちばん小さい答えは次の 3 行 (値は作り物の例)。

```yaml
id: mihon_seisakusho
name: 見本製作所
port: 8003
```

このファイルを、例えば `~/mihon_seisakusho.yaml` に保存する。clone した seizou のフォルダで `uv run seizou new ~/mihon_seisakusho.yaml` を打つ (`--demo` を付けない。作り物のデータを入れない)。PyPI だけで入れた人は `seizou new ~/mihon_seisakusho.yaml` を打つ。`seizou new` は答えを置き場 (`~/seizou-sites/<id>/`) の `answers.yaml` に写し、終わりに起動の 1 行を出す (触り方の 3 と同じ)。答えの形が違うと、「止まりました: …」の 1 行を出して止まる (例 `name` だけの YAML では「止まりました: 答えの YAML に id・port がありません: <答えの YAML のパス>」)。YAML を直して、もう 1 度打つ。

書ける鍵は次のとおり。

| 鍵 | 要るか | 書き方 |
|---|---|---|
| `id` | 要る | 会社の id。英小文字で始め、英小文字と数字と `_` だけで書く (ハイフンと大文字は使えない)。置き場のフォルダ `~/seizou-sites/<id>/` の名前になる |
| `name` | 要る | 会社の名前 |
| `port` | 要る | 起動の 1 行の runserver のポート。整数で書く。ほかの会社の置き場と同じ番号にしない |
| `industry` | 任意 | 業種。業種の見本 (機械加工・表面処理・鋳造・板金) の名前か言い換えに当たると、部品マスターの項目・工程・向く設定を見本から最初に入れる (答えに書いた項目と設定が勝つ) |
| `recipe` | 任意 | 書けるのは `none` だけ。業種の見本を入れない |
| `company` | 任意 | 会社の情報。下に `address` (住所)・`phone` (電話)・`bank_account` (振込先)・`registration_no` (登録番号。T と 13 桁の数字) を書く。値は字で書き、数に読める値は引用符で囲む |
| `logo` | 任意 | 会社のロゴ。答えの YAML のあるフォルダから見た、PNG か JPEG の絵のファイルのパス |
| `item_fields` | 任意 | 部品マスターに足す項目の並び。1 つの項目に `label` (見出し)・`type` (`text`・`number`・`date`・`choice`・`bool`)・`required` (必須)・`in_list` (一覧に出す)・`searchable` (検索に使う) を書き、`type` が `choice` なら `choices` (選び肢の並び) も書く |
| `settings` | 任意 | 選べる設定。鍵と既定は[「選べる設定」](settings.md)にある。書かない鍵は既定になる |
| `partner_base_urls` | 任意 | `--demo` のときだけ使う。作り物のつながりの種の受け口の頭 (相手の会社の id → 置き場の URL の頭) |

答えの YAML の雛形を出す命令は無い。Claude Code を使う方は、`/seizou:build` の 3 問に答えると、同じ形の答えの YAML が書かれて置き場が立つ ([「Claude Code から使う」](plugin.md))。

### 試した置き場から使い始める

作り物の 2 社の置き場には作り物のデータが入っていて、開発の設定 (自動ログイン) のままになっている。社内で使い始めるときは、次の 3 つを順に行う。

1. 作り物のデータの無い置き場を、自分の会社の答えの YAML で作り直す (上の `seizou new`。`--demo` を付けない)。作り物の 2 社の置き場は、試すためだけに使う。
2. 新しい置き場の `.env` の `SEIZOU_DEV_AUTO_LOGIN` を 0 にし、起動し直す。値が 1 のままだと、その URL を開ける人は誰でも、ログインせずに管理者として入る。`seizou new` は新しい置き場の `.env` にも `SEIZOU_DEV_AUTO_LOGIN=1` を書くので、この手は 1 の後に行う。
3. 管理者のパスワードを変える。新しい置き場で `<python> manage.py changepassword admin` を自分の端末で打つ。

本番で使うときの決まりと点検 (`<python> manage.py seizou_doctor --production`) は、[「本番で使う」](production.md)と[「運用の手引き」](operations.md)にある。
