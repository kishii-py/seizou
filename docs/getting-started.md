# 入れて触る (前提と触り方)

読み手: seizou を初めて触る方。手元の PC に作り物の 2 社を立てて、画面で通す所までを書く。入口は [README](../README.md)。

## 前提

触る前に要る物と、どこまで確かめてあるか。

| 項目 | 要るか・状態 |
|---|---|
| Claude Code の契約 | プラグイン (立ち上げの命令 `/seizou:build`) で立てるときは要る。下の「触り方」の Python の命令 `seizou new` で立てるときは要らない |
| 外のネット | 最初に入れるときだけ要る (uv と Python の依存を取る)。CSS を作り直す道具 (Tailwind CSS と daisyUI) は、開発のときだけ取る。画面の CSS と JS とフォントは配布物に同梱していて、動かすときに外へ取りに行かない |
| OS | 作者の手元は macOS。Linux と Windows は CI (GitHub Actions) の試験だけで、手で通した確認は会期後 |
| 端末の道具 | `git` と `uv` (Python の道具) が要る。git は git-scm.com の配布物、uv は公式の 1 行 (`curl -LsSf https://astral.sh/uv/install.sh \| sh`) で入る。`/seizou:build` は uv が無ければ自分で入れる |
| 費用 | ソフトは無料 (Apache-2.0)。かかるのは、Claude Code の契約 (プラグインで立てるときだけ)・注文書の読み取りと AI チャットの API の費用 (読んだ分だけ。読み取り 1 枚の実測は下の行)・置き場を VPS に置くならその月額 (手元の PC でも動く) |
| PDF の帳票 | extras `[pdf]` (WeasyPrint) と、OS の pango が要る。納品書と請求書の詳細に、印刷用の画面と PDF の入口がある。PDF を作れないときは PDF を作らず、印刷用の画面に「PDF の準備がありません」の知らせを出す (印刷用の画面は使える。`seizou.core.reports` の約束) |
| 注文書の読み取り | 使う会社だけ、Anthropic の API の鍵 (環境変数 `ANTHROPIC_API_KEY`) が要る。読んだ分だけ API の費用がかかり、製品は Claude Code の契約の枠を使わない。鍵が無い会社では、「注文書を読み取る」の画面に黄の知らせ (「AI の鍵が無いので読み取りは使えません。受注を手で入れてください。」。アカウント管理の権限がある人には鍵の置き場と設定の画面への link も) が出て、入力の欄とボタンは出ない。ほかの画面は鍵が無くても動く。読み取り 1 枚の実測: 作り物の注文書 (1 ページ・明細 3 行) の PDF 1 枚で、入力 2,805 トークン・出力 295 トークン・4.6 秒 (11-08 12:40 ごろ。claude-opus-5-5。作者の Mac の A 社の置き場で `extract_to_inbox` を 1 回)。料金表 (入力 $4・出力 $20 / 100 万トークン。2026-10 時点) で約 0.017 ドル = 1 ドル 150 円なら約 2.6 円。明細の行が増えると出力のトークンが増える |
| AI チャット | 使う会社だけ、注文書の読み取りと同じ鍵 (環境変数 `ANTHROPIC_API_KEY`) が要る。鍵が無い会社では、右下の丸いボタン (AI に質問) で開く窓に 1 文だけが出て、入力の欄は出ない。質問と、画面の説明書と、道具の結果 (部品・受注・指示書・出荷・業務マニュアルの中身。単価と金額を含む) を Anthropic の API へ送り、読んだ分だけ費用がかかる。答えは誤りうるので、数は答えの link の先の画面で確かめる (SECURITY.md)。受注の登録・出荷・計画の置き直しは、AI が保存せず提案のカードになり、人が「承認」を押してから保存される |
| フィードバックの AI の聞き取り | 使う会社だけ、AI チャットと同じ鍵 (環境変数 `ANTHROPIC_API_KEY`) が要る。鍵が無い会社では、フィードバックの入力の画面に AI の聞き取りのカードが出ず、入力の形だけで伝える。利用者が書いた字と、画面の目録・画面ごとの説明書・会社の設定 (会社の名前・選べる設定の今の値・入っている Django の部品) を Anthropic の API へ送り、読んだ分だけ費用がかかる (使う model は設定 `feedback_model`。既定は安い haiku)。受注・部品・出荷のデータを読む道具と、書く道具は渡さない。下書きは会社の中に残る。GitHub に送るのは、アカウント管理の権限がある人がトークンを置いた会社で「GitHub に送る」を押した確認済みの物だけ ([「フィードバック」](screens.md)) |
| 所要時間 | 1 社なら、インストールから動き出すまで 50.6 秒 = 約 50 秒 (11-08 07:40 ごろ。作者の Mac。uv のキャッシュを空にして測った = `git clone` 32 秒・`uv sync --locked` 7 秒・`seizou new … --demo` 11 秒・runserver を起動して /health/ が 200 になるまで 1 秒。動画の語りの「50 秒」はこの値 = `seizou new` で立てる方法の値で、`/seizou:build` の 3 問に答える時間は入っていない。Claude Code のプラグインで立てる方法は 2 分 54 秒 = 入れる 34 秒 + 3 問に答えて画面が開くまで 140 秒。11-08 12:30 ごろ、uv の cache あり)。2 社なら 49 秒 (11-08 04:20 ごろ。同じ条件 = `git clone` 24 秒・`uv sync --locked` 5 秒 (依存を取る。Python 3.12 は入れてある)・`seizou new … --demo` を 2 回で 19 秒・runserver を起動して /health/ が 200 になるまで 1 秒。外のネットの速さで変わる) |

## 触り方

今ある入れ方は、端末で命令を打つ方法だけで、作者の手元 (macOS) で通した物。Linux と Windows は CI の試験だけで、手で通した確認は会期後。PDF の帳票には WeasyPrint と OS の pango が要る (無くても画面は動く)。

端末の開き方は、Mac は「ターミナル」、Windows は PowerShell、Linux は端末のアプリ。

初めて触る方に向けた、Claude Code を使わない方法。2 社の会社のプロジェクトを作って作り物のデータを入れ、起動してログインし、受注から出荷と納品書までと、A 社から B 社へ注文を送る流れを画面で通せる。鍵 (`ANTHROPIC_API_KEY`) が無くても、注文書の読み取りと AI チャットとフィードバックの AI の聞き取り以外の全部の画面が動く。鍵のある会社でも、AI は受注の登録や出荷を勝手に保存せず、人が提案のカードの「承認」を押すまで保存しない。

1. 入れる (版 v0.1.0 の tag から): `git clone --branch v0.1.0 https://github.com/kishii-py/seizou.git && cd seizou && uv sync --locked` (帳票の PDF も使うなら `uv sync --locked --extra pdf`)。PyPI の `pip install seizou` でも部品は入るが、例の 2 社の答えと種 (`examples/companies/`) は clone した物を使う
2. 会社のプロジェクトを作る命令を、`examples/companies/` にある 2 社の答えの YAML で 1 回ずつ打つ: `uv run seizou new examples/companies/a_machining.yaml --demo` と `uv run seizou new examples/companies/b_plating.yaml --demo`。この命令が会社のプロジェクトを `~/seizou-sites/<会社の id>/` に作り、データベースを用意し (migrate)、管理者を 1 人作る。置き場の親は環境変数 `SEIZOU_SITES_DIR` で変えられる。`--demo` は作り物のデータを入れる指定だ。答えの YAML と同じ場所の `<会社の id>/` (種のフォルダ) から、部品・取引先・部品の取引先・工程・受注・つながりと、標準の工程・図面・指示書・出荷・納品書・請求書と、部品が持つ種 (業務マニュアル・権限 (作り物の部署とアカウント)・在庫・出荷の知らせと検収・入金) を読み込む。読み込んだ種類ごとに「<種類>: 入れた n 件・飛ばした m 件」の行を出し、最後に「作り物のデータを登録しました: <種のフォルダ>」の文を出す。種の中身は `examples/companies/README.md` に書いてある。
   答えの YAML の `industry` が業種の見本 (`src/seizou/recipes/` の 4 本 = 機械加工・表面処理・鋳造・板金) の名前か言い換えに当たると、`seizou new` は部品マスターの項目・工程・向く設定を見本から最初に入れ、「業種の見本 (<業種>) から入れました: …」の行を出す (答えの YAML に書いた項目と設定が勝つ。見本を入れないときは答えの YAML に `recipe: none` と書く)。例の 2 社の答えと種は見本と同じ中身なので、足される物は無い。
   答えの YAML に `logo:` (答えの YAML のあるフォルダから見た相対のパスで、PNG か JPEG の絵のファイル) を書くと、`seizou new` は会社のロゴと、ロゴから作った印 (favicon。ブラウザのタブに出る絵) も入れる。後から設定の画面の「会社の情報」でロゴを上げても、印ができる。印は会社の置き場で `manage.py seizou_company_icons` を打つと、ロゴから作り直せる (データベースの表には書かない)。
3. 2 社を別のポートで起動する。A 社 (若葉精機。作り物の名前で、機械加工の注文を送る側) は 8001、B 社 (白樺めっき工業。作り物の名前で、表面処理の注文を受ける側) は 8002。起動の 1 行 (A 社の例。`seizou new` が終わりに、置き場と Python の場所を埋めた同じ形の 1 行を出す): `cd ~/seizou-sites/a_machining && <seizou を clone した場所>/.venv/bin/python manage.py runserver 8001`
4. ブラウザで http://127.0.0.1:8001/ と http://127.0.0.1:8002/ を開く。開発の設定 (`.env` の `DEBUG=1` と `SEIZOU_DEV_AUTO_LOGIN=1`。`seizou new` の既定) では、ログインの画面を飛ばして管理者として開く (`/login/` を開いたときだけログインの画面が出る)。ログインするときの ID は `admin`。いつもログインの画面を見るには `SEIZOU_DEV_AUTO_LOGIN` を 0 にする。管理者 `admin` のパスワードは `seizou new` の出力に 1 度だけ出る。作り物のアカウントは 3 つで、パスワードは 3 つとも `seizou-demo-1103`。外から開ける置き場では `--demo-password random` を使う (3 人に別々の乱数を作り、`seizou new` の出力に 1 人 1 行で出す)。`genba` (現場) は製造の画面 (指示書・生産計画・進捗) と部品マスターだけを開き、進捗の実績を入れられるが、伝票とマスターは登録できない。`jimu` (事務) は出荷の画面で伝票を作れるが、単価と金額は「—」で出て、金額に関わる操作 (受注の登録・変更・取消、発注、納品書、請求書と入金) は入口が出ない (金額を見られない人は金額に関わる操作をしない = 作者の決め 11-07 21:00 ごろ)。`keiri` (経理) は請求書を作って印刷し、金額を見られる。管理者のパスワードを変えるには、会社の置き場で `<python> manage.py changepassword admin` を自分の端末で打つ (`/seizou:build` で立てたときは、パスワードを会話に出さずに `~/seizou-<会社の id>-admin.txt` に書くので、自分で開いてログインし、ログインしたらファイルを消す)。2 社は同じブラウザで開いたままにできる (cookie の名前を会社ごとに分けている)。
5. 見る順は、受注 → 出荷が止まる → 受信した注文。手順は次のとおり (ほかの画面の入口は[「画面の一覧」](screens.md)にある)。
   1. A 社で、ダッシュボードから「受注」を開き、「新規登録」で受注を 1 件入れる (得意先と明細の行を選ぶ)。
   2. 「出荷」の「新規登録」で、その受注の明細に、受注より多い数を入れて保存する。A 社は受注より多い出荷を止める設定なので、赤の知らせが出て保存されない。
   3. B 社で同じことをすると、黄の知らせと「このまま保存」のボタンが出て、押せば現物のとおり保存できる (設定の違いは[「選べる設定」](settings.md))。
   4. 部品の「新規登録」の画面を開くと、会社ごとの項目 (A 社は「材質」と「図面の版」、B 社は「処理の種類」と「膜厚 (μm)」) が並ぶ。
   5. 2 社の間で注文を送り合う前に、2 社の `.env` に同じ値の鍵を置き、2 社を起動し直す。値は A 社の置き場で `<python> manage.py seizou_secret SEIZOU_PARTNER_B_PLATING_SECRET` を自分の端末で打って作る。出た 1 行を A 社の `.env` に足し、同じ値を B 社の `.env` に `SEIZOU_PARTNER_A_MACHINING_SECRET=<値>` の 1 行で足す (名前の決まりは[「取引先とつなぐ」](connect.md))。
   6. A 社で「発注」の「新規登録」を保存すると、B 社へ注文が送られる。
   7. B 社の「受信した注文」に新しい行が出るので、行の操作の「受け入れる」を押す。「注文を受け入れる」の画面で、相手の品番ごとに選んである自社の部品を確かめて保存すると、B 社の受注になる。
6. 続けて、2 社の間の往復とお金の流れを見る。B 社が受け入れると、A 社の発注の状態が「相手が受け入れた」になる (注文回答)。B 社がその受注を出荷すると、A 社の発注の詳細の明細の「出荷の知らせ」の列に出荷が出る。A 社がその出荷の「受入を記録する」で受け入れた数を入れると、A 社の在庫に入り、B 社の受注の明細の「検収」の列に受け入れた数が返る。請求書の詳細の「入金を記録する」で入金を入れると、残と入金の状態が変わる。
7. 一覧の絞り込みの期間の欄の下の「今日・今週・今月・先月」を押すと、始めと終わりが会社の時刻で入り、表がその期間に絞られる (週は月曜から)。上の帯の鈴は、受信した注文と、自分が送ったフィードバックの直した・見送った・返事のうち、まだ見ていない物の数を出し、押すと新しい順に並ぶ (開くと印が消える)。☆ で登録した画面は、上の帯の ☆ の小窓とダッシュボードの「よく使う画面」のほか、左のメニューの「ブックマーク」の組にも登録の順に並ぶ。上の帯の「使い方」は画面ごとの説明書の目次を開き、「PDF」で冊子にする (作り物の 2 社には、画面ごとの説明書が入っている)。画面の右下の丸いボタン (吹き出しの絵。読み上げの名前は「AI に質問」) で開く AI チャットは、鍵 (`ANTHROPIC_API_KEY`) を置いた会社だけで使え、受注の登録や出荷は、提案のカードを人が「承認」してから保存される。左のメニューの[「フィードバック」](screens.md)からは、困りごとや要望を書いて残せる。毎日の控えは会社の置き場で `<python> manage.py seizou_backup` を打って取る ([「毎日の運用」](production.md))。
