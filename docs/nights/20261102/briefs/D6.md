### 1. `src/seizou/connect/signing.py`

標準の library だけ (`hmac`・`hashlib`・`base64`・`time`)。Django・requests に触れない。

| 公開する物 | 約束 |
|---|---|
| 見出しの名前の定数 3 つ | `webhook-id`・`webhook-timestamp`・`webhook-signature` (小文字) |
| `sign(secret, msg_id, timestamp, body)` | 「番号.時刻.本文」(番号と時刻は文字列、時刻は UNIX 秒の整数、本文は受けた bytes のまま。整形し直さない = 05 の 5 節) を HMAC-SHA256 で署名し、`v1,` + base64 の値 (署名の見出しの値) を返す |
| `headers_for(secret, msg_id, body, *, now=None)` | 3 つの見出しの辞書を返す (送る側 = 11/3 の `send_order` が使う)。番号は呼ぶ側が uuid4 で作って渡す (01 の 4 節: 注文のデータの番号 = `webhook-id`) |
| `verify(secret, headers, body, *, now=None, tolerance=300)` | 見出しの名前の大小文字を区別せずに 3 つを読む。時刻が整数として読め、`now` との差が ±tolerance (5 分 = 300 秒。05 の 5 節。過去と未来の両側) の中にあり、署名の見出しの中の空白区切りの候補のうち `v1,` で始まる物のどれかが `hmac.compare_digest` で合えば、番号 (文字列) を返す。合わなければ `SignatureError` を投げる |
| `SignatureError` | 例外の型 1 つ。理由の種類を持つ (見出しが無い・時刻が読めない・時刻の幅の外・署名が合わない)。鍵違いと改ざんはどちらも「署名が合わない」(違いを外に出さない)。connect の `receive` (11/3) がこの種類を日本語の断る理由に直す。鍵の値を例外の文に入れない |

- 鍵: Standard Webhooks の公開の仕様の符号化 (接頭辞つきの base64) をほどいた bytes を HMAC の鍵にする。符号化されていない生の文字列を受けるかは未確認なので受けない (小さい方)。鍵の値の例をファイルに書かない。鍵をログや例外の文に出さない (05 の禁じること)。「鍵の形を書かない」の決まりは鍵の値と社内で使っている鍵の形のことで、公開の仕様の接頭辞は禁止語の一覧に当たらないと本体が確かめてある (接頭辞の文字列を module に書いてよい)。
- `now` は引数で渡せる (テストが時刻を動かすため)。既定は今の時刻。
- 同じ番号の 2 回目の約束 (module の docstring に文で書く): この module は状態を持たず、再送を見分けない。見分けるのは connect の `receive` (11/3) で、`verify` が返した番号を `Inbox` の番号の一意の制約 (R11) に当て、2 回目は新しい行を作らず、1 回目と同じ 200 を返す (05 の 5 節「同じ番号は 1 回だけ登録し、`Inbox` に入れて 200 を返す」の読み。送る側が再送をやめられるように)。時刻の幅の外の再送は署名の段で断る (R12)。登録した取引先の鍵を引くのも `receive` の仕事 (この module は鍵を受け取るだけ)。
