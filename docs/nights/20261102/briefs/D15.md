### 2. `src/seizou/connect/services.py` (2 段目)

| 関数 (10.4 のまま) | 決まりと動き | 返す物 |
|---|---|---|
| `register_connection(partner, url, secret_env, direction, user)` | `direction` が 2 値以外なら `ValueError`。`secret_env` が環境変数の名前の形 (`^[A-Z][A-Z0-9_]*$`) でなければ `ValueError` (値を受け取らない。`=` を含む物や小文字の物を断る)。`url` は向きが `send` のとき空でなければ `URLField` の検査に通る物 (`receive` のときは空でよい)。`atomic` の中で作る | `Connection` |
| `receive(raw_body, headers)` | 下の手順。`raw_body` は bytes、`headers` は見出しの名前 → 値の mapping (Django の `request.headers` でも素の辞書でもよい) | `Inbox` (作った物か、同じ番号の 1 回目の物) か、断る理由の日本語の文字列 |

`receive` の手順 (05 の 5 節の「受ける」の段落の順):

1. 取引先を見分ける (R12)。Standard Webhooks の見出しには差出人が無いので、向きが `receive` の `Connection` を全部 (`select_related("partner")`) 読み、順に試す: `secret = os.environ.get(connection.secret_env)` が空なら飛ばす (「鍵が未設定」をログに 1 行。名前だけ出し、値は無いので出ない)。`verify(secret, headers, raw_body)` が通れば、その取引先に決めて番号 (文字列) を得る。`SignatureError` の `reason` が `MISSING_HEADER`・`INVALID_TIMESTAMP`・`TIMESTAMP_OUT_OF_TOLERANCE` なら、鍵と関係なく決まる誤りなので、その場でその理由を返す (ほかの鍵を試さない)。`SIGNATURE_MISMATCH` なら次のつながりへ。鍵の符号化の誤りの `ValueError` は「設定の誤り」としてログに 1 行 (名前だけ) 出して次へ。全部で合わなければ断る (未登録の相手と鍵違いを区別しない = 05 の「登録した取引先からの、署名の合う物だけ」)。本文は署名が通るまで読まない (信用できない本文を先に `json.loads` しない)。
2. 番号を `uuid.UUID(番号)` で読む。読めなければ断る (「番号が uuid の形ではありません」)。版 (uuid4 か) は見ない (案)。
3. 本文を `json.loads(raw_body.decode("utf-8"))` で読む。読めない・辞書でない なら断る (「本文が JSON の形ではありません」)。本文の中の番号は見ない (見出しの番号が正 = 01 の 4 節。署名が両方を守る)。
4. R11: `transaction.atomic()` の中で `Inbox.objects.create(message_id=…, partner=…, kind="order", payload=…)`。`IntegrityError` (同じ番号が既にある) なら `Inbox.objects.get(message_id=…)` を返す (新しい行を作らず、1 回目と同じ物 = D6 の約束。別の取引先から同じ番号が来ても 1 回目の行を返す)。`create` を入れ子の `atomic` で囲み、外のトランザクションを壊さない。
5. 断るときは `logging.getLogger("seizou.connect")` に理由と `webhook-id` の値 (あれば) を 1 行だけ出す。本文と鍵の値をログに出さない。受信箱には入れない (05 の 5 節)。

断る理由の日本語 (案。何が起きて何をすればよいかの 1〜2 文):

| `SignatureError.reason` など | 返す文 |
|---|---|
| `MISSING_HEADER` | 署名の見出しがありません。`webhook-id`・`webhook-timestamp`・`webhook-signature` の 3 つを付けて送ってください。 |
| `INVALID_TIMESTAMP` | 時刻の見出しが読めません。UNIX 秒の整数で送ってください。 |
| `TIMESTAMP_OUT_OF_TOLERANCE` | 送った時刻が 5 分の幅の外です。時計を合わせて送り直してください。 |
| `SIGNATURE_MISMATCH` (全部の鍵で合わない。つながりが 1 つも無いときも) | 登録した取引先の署名と合いません。つながりの登録と鍵を確かめてください。 |
| 番号が uuid でない | 番号 (`webhook-id`) が uuid の形ではありません。 |
| 本文が JSON でない | 本文が JSON の形ではありません。 |

### 3. 受け口の view と URL (2 段目)
