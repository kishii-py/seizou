## 守ること

- 触ってよいのは、この依頼書の「触ってよい物」に名指しした物だけ。ほかの app・`src/seizou/core/`・`tests/test_r*`・`RULES.md`・`plugin/hooks/` は、名指しが無ければ触らない。土台の形 (公開する関数の名前と引数・土台の画面の継承の形・決まりの番号) は変えない。
- 仕様 (`plan/spec/`) のとおりに作る。仕様に無い物を足さない。迷ったら小さい方を選び、迷った事を記録に書く。部品に足りない物は、自分の記録のファイル (「終わりにすること」のファイル) に要望として 1 行で書き残す。
- このリポジトリは独立している。手元のほかのリポジトリ (計画のフォルダの外の物。読めない設定にしてある) を読まず、使わず、写さない。
- 客先と取引先の名前、社内の部品の名前、鍵の形を、ファイルにも commit の文にも書かない。実在の会社名と人名を書かない。作り物のデータだけを使う。
- 画面は core の土台を継承し、数と金額を変える処理は `services` を通し、SQL を直接書かず、部品の表を変えず、class 名を途中で組み立てず、CSRF の見出しは土台の 1 か所 (R13〜R19)。
- 1 本の仕事は 1 つの範囲。同じファイルをほかのレーンと同時に触らない。
- テストを書き、pytest を回し、通った本数を記録に書く。通らないテストを消して通さない。決まりの検査を無効にしない。
- 手元の commit まで。push しない。commit は明示したパスだけ (`git add -A` と `git add .` を使わない)。commit の前に `git status` で外の変更が混ざっていないかを見る。commit の文に客先の話を書かない。commit の末尾に `Co-Authored-By: Claude Fable 5.1 <noreply@anthropic.com>` を付ける。履歴を書き換えない。

- 止まったら、どこで止まったかを自分の記録のファイルに 1 行書いて終わる。粘らない。
