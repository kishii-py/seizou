# 取引先とのつながり

読み手: 会社のシステムを預かる人。取引先と注文を送り合う仕組みと、社内でそろえる形を書く。入口は [README](../README.md)。

## 取引先とつなぐ

取引先と注文をやり取りするときは、注文 1 件を 1 つの注文のデータ (取引先との間でやり取りする、注文 1 件の JSON) にし、相手ごとの鍵で署名して、相手の注文を受け取る窓口へ送る。受けた側は署名と送った時刻 (前後 5 分の幅) を確認し、合う物だけを「受信した注文」に入れる。受信した注文は、人が受け入れるまで受注にならない。同じ番号の注文のデータは 2 回届いても 1 件にする。鍵の値は両方の会社の `.env` に同じ値を置き、環境変数の名前は `SEIZOU_PARTNER_<相手の会社の id を大文字にした物>_SECRET` にする (例: A 社が B 社へ送るときの名前は `SEIZOU_PARTNER_B_PLATING_SECRET`)。値の形は SECURITY.md に書いた。

送る側は発注の「新規登録」を保存すると、同時に注文のデータを送る。受けた側の「受信した注文」の画面は、開いたまま 2 秒ごとに新しい行を足す。受け入れの画面では、部品の取引先の表から自社の部品を初めから選んであり、受け入れると受注になる。状態の名前と意味は下の「発注の状態」の表にある。

つながりは、右上の利用者のメニューの「設定」→「普段は触らない物」の「取引先との接続 (つながり)」→「新規登録」で登録する。1 つの取引先に、送る向きと受ける向きの 2 行を登録する。往復には 2 社とも両方の向きが要る (送る向きだけでは、相手からの注文回答・出荷の知らせ・検収を受けられない)。2 行の鍵の置き場の名前は同じにし、受ける向きの行の受け口の URL は空にする。Claude Code を使う会社は、`/seizou:connect` が同じ登録を会話で案内する。

鍵の値は、会社の置き場で `manage.py seizou_secret <鍵の置き場の名前>` を担当者が自分の端末で打って作る。値は `<鍵の置き場の名前>=<値>` の 1 行で画面に 1 度だけ出て、ファイルには書かれない。相手の会社には = の後ろの値を人の手で渡す。値を `.env` に置いたら、2 社とも会社のシステムを起動し直す (起動するときに `.env` を読むため)。作り物の 2 社のつながりは `--demo` の種に入っている。つながりの一覧の「鍵の設定」で、鍵が済みかまだかが見える。

手元のデモは同じ PC の 2 社で動かす。離れた 2 社が往復するには、2 社とも外から届く URL が要る (注文は受ける会社の受け口へ、注文回答・出荷の知らせ・検収は発注した会社の受け口へ届くため)。VPS 1 台に 2 社分を https で立てて手でつなぐ手順は [docs/vps.md](vps.md) にあり、動画の送り合い (1:35〜1:59) はこの形で立てた実在の 2 社の置き場で撮った。置き場を立てる命令と、公開の URL を持たない会社のための中継は、これから作る ([これからの道筋](roadmap.md))。

## 発注の状態

発注の状態は、相手の返事と、受入の記録と、取消で変わる。相手が受け取ったという返事で「下書き」から「送った」になり、相手の答え (注文回答) で「相手が保留した」「相手が条件付で受けた」「相手が受け入れた」「断られた」のどれかになる。注文回答が届いた日時は、発注の一覧の「注文回答の日時」の列に出る。

| 状態 | 意味 | 次にすること |
|---|---|---|
| 下書き | まだ相手に届いていない (つながりが無い・鍵が無い・相手が受けなかった、など)。送ったが届かなかった発注は、届かなかった訳が発注の詳細の黄の知らせに出る。つながりの無い取引先への発注は送らないので、黄の知らせは出ない | 直したら、発注の詳細の「再送」を押す (下の「届かないとき」) |
| 送った | 相手が受け取り、相手の「受信した注文」に入った。相手の答えはまだ届いていない | 相手の答えを待つ (ダッシュボードの「返事を待つ発注」に数えられる) |
| 相手が保留した | 相手が答えを保留した。本当の答えは後で届く | 答えが届くのを待つか、相手と話して決める |
| 相手が条件付で受けた | 相手が単価・数量・納期を直して受け入れた。相手の回答単価・回答数量・回答納期は、明細の下の黄の行に出る | 合わせるときは「変更」で発注を直して送り、合わせないときは相手と話して決める |
| 相手が受け入れた | 相手が発注のとおりに受け入れた | 物が届いたら「受入を記録する」 |
| 一部納品 | 相手が受け入れた発注のうち、受入が一部だけの物 | 残りが届いたら「受入を記録する」 |
| 断られた | 相手が断った | 相手と話して決める。取り消すときは、発注の詳細の「⋯」の「取消」 |
| 納品された | 全部の明細の受入を記録した (取り消した明細は数えない) | 受入の行の「検収」の列で、検収が相手に届いたかを見る |
| 取消 | 発注を取り消した。送った発注は、取消を相手へ送る | 要るときは、新しく発注を入れる |

「下書き」のまま受入を記録した発注は、全部の明細の受入を記録するまで「下書き」のまま。全部を記録すると「納品された」になる。

## 届かないとき

届かない物は、自動では送り直さない。人が画面のボタンを押して送り直す。

- 発注: 発注の詳細に、黄の知らせ「注文は相手に届いていません。<理由> 直したら「再送」を押してください。」が出る。直したら「再送」を押す。状態が「下書き」の発注は、ダッシュボードの今日やることの「まだ送っていない発注」にも数えられる。
- 注文回答: 受信した注文の詳細の「注文回答」の「送り直す」。
- 出荷の知らせ: 出荷の詳細の「出荷の知らせ」の「送り直す」。
- 検収: 発注の詳細の、受入の行の「送り直す」。
- 会話: 自社が書いた言葉の下の「送り直す」。

送り直す前に、次の 4 つを見る。1 つ目は、送る向きのつながりの受け口の URL (相手の担当者に聞いた URL か)。2 つ目は、相手の会社のシステムが動いているか。3 つ目は、2 社の鍵の置き場の名前と値と、`.env` に置いた後に起動し直したか。4 つ目は 2 社の時計で、受ける側は送った時刻を前後 5 分の幅で確かめる。VPS に立てた置き場は、[docs/vps.md](vps.md) の 17 の「届かないとき」の 5 つも見る。

## 離れた相手と手元の PC だけの会社

外から届く URL を持たない会社 (手元の PC だけの会社) にできる事は 2 つある。同じ PC の 2 社の送り合い (手元のデモ) と、下の「相手が seizou を入れていないとき」の道。できない事は、離れた相手との往復。相手へ注文を送れても、注文回答・出荷の知らせ・検収が自社の受け口へ届かない。公開の URL を持たない会社のための中継は、これから作る ([これからの道筋](roadmap.md))。

## 相手が seizou を入れていないとき

発注する側は、発注の詳細の「印刷用の画面」か「PDF」で発注書を出し、紙かメールで送る。2 つのボタンは、金額を見られる人にだけ出る。つながりの無い取引先への発注は、状態が「下書き」のままで、ダッシュボードの「まだ送っていない発注」に数えられる。受入は記録でき、全部の明細の受入を記録すると「納品された」になる。

受注する側は、相手の注文書を受注の一覧の「注文書を読み取る」で読み取るか、受注を手で入れる。読み取りは、管理者が AI の鍵を設定した会社で使える。鍵が無いときは、読み取りの画面に「AI の鍵が無いので読み取りは使えません。注文書の読み取りは、管理者が AI の鍵を設定すると使えます。受注を手で入れてください。」と出る。

## 社内の 1 つの形

取引先ごとに品番や注文書の書式が違っても、自社の中では部品マスターの品番で 1 つにそろえる (外は多様なまま、中は 1 つの形)。取引先の品番と自社の品番の対応は、マスターの Django の部品 (`seizou.masters`) の「取引先の品番」の表に持つ。注文の項目の名前は中小企業共通 EDI (中小企業どうしが注文などのデータをやり取りするための、共通の項目の決まり) の、注文の必須の項目を元にした。会社は使わない項目を設定 ([「選べる設定」](settings.md) の `hidden_fields`) で隠す。
