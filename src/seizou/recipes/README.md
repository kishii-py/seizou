# 業種の見本 (レシピ)

新しい会社を立てるときに、業種らしい部品マスターの項目・工程・向く設定を最初から入れるための YAML を置く。答えの YAML の `industry` (問 1 の業種) が、見本の名前か言い換えに当たると、`seizou new` が答えに無い項目と設定を見本から補い、工程を見本から入れる。答えの YAML に書いた項目と設定が勝つ (見出しが同じ項目と、鍵が同じ設定は答えの物を使う)。工程は作り物のデータの種 (`--demo`) の後に入れ、工程コードか名前が同じ工程が既にあれば飛ばす (種の工程が勝つ)。答えの YAML に `recipe: none` の 1 行を書けば、見本を入れない。見本は全部作り物で、実在の会社名・人名・品番は書かない。

この置き場は部品 (`src/seizou/`) の中にあるので、pip で入れた版でも `seizou new` が読む。

## 4 本の見本

| id | 業種 | 言い換え | 項目 | 工程の並び | 向く設定 |
|---|---|---|---|---|---|
| `machining` | 機械加工 | 切削加工・切削・旋盤加工・マシニング加工・精密機械加工 | 材質・図面の版 | 旋削 → フライス加工 → 検査 | 受注より多い出荷を止める (`over_shipment: stop`) |
| `plating` | 表面処理 | めっき・メッキ・鍍金・電気めっき・塗装・アルマイト・化成処理 | 処理の種類・膜厚 (μm) | 前処理 (脱脂・酸洗) → 表面処理 → 検査 | 受注より多い出荷を知らせる・分納を許す (`over_shipment: warn`・`partial_shipment: true`) |
| `casting` | 鋳造 | 鋳物・鋳物製造・砂型鋳造・精密鋳造・ダイカスト | 材質・型の番号・重さ | 造型 → 鋳込み → 仕上げ → 検査 | 受注より多い出荷と指示書の数を知らせる・分納を許す (`over_shipment: warn`・`over_workorder: warn`・`partial_shipment: true`) |
| `sheet_metal` | 板金 | 板金加工・精密板金・製缶・製缶板金 | 板厚・材質・曲げの数 | 抜き → 曲げ → 溶接 → 検査 | 受注より多い出荷を止める (`over_shipment: stop`) |

業種の字は、字の幅と空白と英字の大小をそろえた後で、名前か言い換えと全部が同じときだけ当たる (一部が同じだけでは当たらない)。かなとカナは同じ字にしないので、「めっき」と「メッキ」は両方を言い換えに書く。

## 1 本の形

1 本の見本は、答えの YAML の部分と同じ形の 4 つの鍵を持つ。鍵は英語、値の字は日本語で書く。

| 鍵 | 書く物 |
|---|---|
| `industry` | `name` (出力に出す業種の名前) と `aliases` (問 1 の答えに当てる言い換えの並び。`name` も入れる) |
| `item_fields` | 部品マスターに足す項目の並び。答えの YAML の `item_fields` と同じ形で、`label`・`type`・`required`・`in_list`・`searchable` の 5 つを全部書く (`type` が `choice` なら `choices` も)。見出しは重ねない |
| `processes` | 工程の並び。1 件は `code` (工程コード。英大文字で始め、英大文字と数字と `_` で 10 字まで)・`name` (100 字まで)・`is_outsourced` (協力企業に出すか)・`sort_order` (並び順。0 以上の整数)・`use_in_plan` (計画に使う) の 5 つ。工程コードと名前は重ねず、計画に使う工程を 1 つ以上置く |
| `settings` | 向く設定。書ける鍵は `order_form`・`partial_shipment`・`over_shipment`・`over_workorder`・`order_number`・`production_plan` だけ (権限・model・メニュー・隠す項目は書かない)。`off` を書くときは引用符で囲む |

`seizou new` は見本を読むときに、知らない鍵・型の誤り・工程コードの重なり・見本どうしの言い換えの重なりを見つけると、ファイルの名前と場所を出して止まる (終わりの番号 2。置き場は作らない)。

## 例の 2 社とそろえてある

機械加工の見本は A 社 (`examples/companies/a_machining.yaml`)、表面処理の見本は B 社 (`examples/companies/b_plating.yaml`) と中身をそろえた。見本の項目は 2 社の答えの項目と同じ並び、見本の設定は 2 社の答えと同じ値、見本の工程は 2 社の種の `processes.yaml` の行と同じ値。だから 2 社を `seizou new … --demo` で立てても項目と工程と設定は増えず、「業種の見本 (<業種>) と同じ物が全部あったので、足した物はありません。」の 1 行だけが出る。見本を変えるときは、2 社の答えと種もそろえる (`tests/test_examples_recipes.py` が見る)。

## 新しい業種の足し方

作品のリポジトリのこのフォルダに、`<業種の id>.yaml` を 1 本置くだけで足せる (id は英小文字と数字と `_`)。名前と言い換えは、ほかの見本と重ねない。置いたら `uv run pytest tests/test_examples_recipes.py` で形を確かめる (試験の `EXPECTED_IDS` と、この README の表にも足す)。見本は部品の中身なので、会社の置き場からは足さない (`/seizou:build` は部品の中身を書き換えない)。
