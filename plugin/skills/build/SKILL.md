# 会社のシステムを立てる

この命令は、工場で PC を任された担当者と話しながら、その会社専用のシステムを手元の PC に立てます。担当者はプログラムを書かない人です。担当者に見せる文は短く平易な日本語にし、専門の言葉を初めて使うときは短い説明を添えます。

## 1. 最初に言うこと

動き出す前に、次の趣旨を 1〜3 行で担当者に伝えます。

- これから質問を 2 つ、1 つずつします。
- 答えると、御社専用のシステムを手元の PC に作って立ち上げます。
- 終わったら、ログインの画面の URL と管理者の ID をお知らせします。

答えの YAML が渡されたときは、質問をせずに進めることを伝えます。

## 2. 前提を確かめる

1. uv (Python とその部品を入れて動かす道具) が入っているかを、`uv --version` で確かめます。
   - 入っていなければ、公式の入れ方を shell で打ちます。macOS と Linux は `curl -LsSf https://astral.sh/uv/install.sh | sh` です。Windows は PowerShell で `powershell -ExecutionPolicy ByPass -c "irm https://astral.sh/uv/install.ps1 | iex"` です。
   - 入れ終わったら、「uv を入れました。Claude Code をいったん閉じて開き直してから、もう一度 `/seizou:build` を打ってください」の趣旨を伝えて止まります。開き直すまで、新しく入れた uv が見つからないためです。
2. git (ファイルの変更を記録する道具) が入っているかを、`git --version` で確かめます。入っていなければ、そのことを伝えて止まります。
3. この後に打つ uv と組み立ての命令には、いつも環境変数 `UV_SYSTEM_CERTS=true` を付けます。会社の proxy (社内と外のネットの間の中継) を通るときに、uv が PC の証明書を使えるようにするためです。

## 3. 答えを集める

答えの YAML (質問の答えを書いたファイル) の場所が命令に添えて渡されたときは、質問を全部飛ばし、その YAML を答えとして使います。たとえば `/seizou:build examples/companies/a_machining.yaml` です。`examples/companies/` の YAML は、作り物の会社の答えです。

渡されなかったときは、次の 2 問を 1 問ずつ聞きます。1 問を聞いたら答えを待ち、答えを読んでから次の問いを出します。

問 1: 会社の名前と業種

- 業種の例は、機械加工や表面処理です。

問 2: 部品マスターに足したい項目

- 部品マスターは、自社の品目 (品番・品名・図面など) を 1 か所にまとめる表です。品番や品名のような基本の項目は、最初からあります。それ以外に会社ごとに持ちたい項目 (例: 材質) を聞きます。
- 項目ごとに、次の 5 つを聞きます。
  - 名前
  - 型 (文字・数・日付・選択肢・はいいいえ のどれか)
  - 必須か
  - 一覧の画面に出すか
  - 検索に使うか

取引先 (注文をやり取りする相手の会社) は聞きません。「取引先は、立ち上げた後に取引先の画面か `/seizou:connect` で登録できます」の趣旨を 1 行だけ伝えます。

答えが無いとき (「特に無い」「分からない」など) は既定を使い、既定を使ったと伝えます。問 2 の既定は「足す項目は無し」です。答えを勝手に補いません。

## 4. 答えを残す

答えを `~/seizou-sites/<id>/answers.yaml` に書きます。このファイルがあれば、後で同じ答えからシステムを作り直せます。

- `<id>` は会社の id (会社を見分ける短い名前) です。英小文字と数字と `_` だけで作り、ハイフンは使いません。
- 答えの YAML が渡されたときは、そのファイルの名前から拡張子を除いた物を id にし (例: `a_machining`)、中身をそのまま写します。
- 新しい会社の id の決め方: 【未決】

答えのファイルの形は次のとおりです。`<...>` の所に答えを入れます。

```yaml
id: <会社の id>
name: <会社の名前 (問 1)>
industry: <業種 (問 1)>
item_fields: []  # 問 2 の答え。部品マスターに足す項目を、答えた順に並べる
settings:        # 会社ごとに選べる設定。この命令では聞かず、この既定の値を書く
  order_form: multi
  partial_shipment: true
  over_shipment: stop
  over_workorder: stop
  order_number: seq
  hidden_fields: []
port: <会社のシステムを開くポートの番号>
```

- `item_fields` の 1 項目に書く 5 つ (名前・型・必須か・一覧に出すか・検索に使うか) の鍵の名前と、型の値の書き方: 【未決】。決まるまでは、`examples/companies/` の例の YAML と同じ書き方にします。
- `port` は、答えの YAML が渡されたときはその値を使います。新しい会社のポートの決め方: 【未決】。ほかの会社と同じ番号にはしません。

## 5. 会社のシステムを作る

組み立ての命令 (答えの YAML から会社のシステムを作る Python の命令) を shell で打ちます。会社のシステムは Django のプロジェクトで、置き場は `~/seizou-sites/<id>/` です。

```
UV_SYSTEM_CERTS=true seizou new ~/seizou-sites/<id>/answers.yaml
```

- 答えが `examples/companies/` の作り物の会社のときは、`--demo` を付けて、作り物のデータも入れます。
- この命令が、置き場を作り、要る物を入れ、データベースを用意し (`migrate`)、管理者を 1 人作り、画面の見た目のファイル (CSS) を作ります。
- 命令が見つからないときや失敗したときは、出力をそのまま担当者に見せて止まります。命令の代わりに `manage.py` や `settings.py` を書いたり、手で作業を補ったりしません。

## 6. 決まりの検査を回す

決まりの検査 (システムのコードが決まりどおりに書かれているかを機械で確かめる仕組み) の命令 `manage.py seizou_check` があれば、会社のシステムの置き場で回します。違反があれば、その内容をそのまま担当者に見せます。ここで違反が出るのは作り手の誤りなので、普通は 0 件です。命令が無ければ飛ばします。

## 7. 起動して知らせる

会社のシステムの置き場で、`manage.py runserver` を答えのファイルの `port` の番号で起動します。起動した後も動き続けるので、後ろで動かします。

- 2 社目を同じ PC で立てるときは、別のポートで立ちます。同じブラウザで両方にログインできます。cookie (ブラウザがログインを覚えておくための小さな記録) の名前は、組み立ての命令が会社ごとに分けて書くので、この命令では何もしません。
- 担当者に、ログインの画面の URL と管理者の ID を伝えます。パスワードは、組み立ての命令の出力のとおりに伝えます。
- `.env` (鍵を置くファイル) の中身と鍵は、画面に出しません。

## 8. 終わりに言うこと

「できた物」と「次にすること」を 3 行以内で伝えます。次にすることの例は、部品マスターに品目を入れること、取引先を登録することです。

## してはいけないこと

- 部品の中身 (`src/seizou/`) を書き換えません。会社ごとの違いは、会社のシステムの `fields/` と設定と `templates/` の上書きで出します。
- 鍵を公開リポジトリに書きません。`.env` は会社のシステムの置き場の中だけに置きます。
- 答えを勝手に補いません。分からなければ既定を使い、既定を使ったと伝えます。
- 答えに無い項目や画面を足しません。
- 手元のほかのリポジトリを読みません。読むのは公開リポジトリと、組み立てた会社のシステムだけです。
- commit の文に客先の話を書きません。
