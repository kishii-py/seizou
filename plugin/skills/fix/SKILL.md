# 決まりの違反を直す

この命令は、決まりの検査 (システムのコードが決まりどおりに書かれているかを機械で確かめる仕組み) が見つけた違反を直します。直すのは会社のシステムの置き場の中のファイルだけです。部品 (seizou。全部の会社で共通の中身) は直しません。担当者はプログラムを書かない人です。担当者に見せる文は短く平易な日本語にし、専門の言葉を初めて使うときは短い説明を添えます。

## 1. 最初に言うこと

動き出す前に、次の趣旨を 1〜3 行で担当者に伝えます。

- 決まりの検査の違反を、御社のシステムの側だけで直します。部品の中身は直しません。
- 直すたびに検査を回し直し、違反が 0 件になったらお知らせします。

## 2. 前提を確かめる

1. 会社のシステムの置き場 `~/seizou-sites/<id>/` に、`manage.py` と `answers.yaml` の両方があるかを確かめます。置き場は、この会話を開いたフォルダか、違反の行のファイルの道から分かります。無ければ、そのことを伝えて止まります。
2. この後で `manage.py` を打つときは、置き場の `README.md` の「起動」の 1 行にある python を使い、置き場のフォルダで打ちます。以下では、その python を `<python>` と書きます。
3. 置き場に `CLAUDE.md` が無ければ、直す前に `seizou ai-docs <置き場>` で AI が守る決まりを置くよう担当者に勧めます。

## 3. 違反を読む

次の順に 1 つだけ読みます。

1. 担当者が、決まりの検査の画面の「この文を写す」で写した文を渡してくれたときは、その文を読みます。
2. 無ければ、置き場の `.seizou/violations.md` を読みます。
3. それも無ければ、置き場で `<python> manage.py seizou_check` を打ち、その出力を読みます。

どれも、1 行に違反が 1 つで、形は `R13 <ファイル>:<行> <文> 直し方: <直し方>` です。最後に `合計: 違反 N 件、黙らせた M 件、走査 K 本` の行があります。写した文には、その前に 1 行の前置きがあります。行が 0 の違反は、ファイルでなくフォルダの違反です。

`.seizou/violations.md` は、開発のサーバー (runserver) を起動したときにだけ書き直されるので、古いことがあります。直した後の確かめは、いつも `seizou_check` で行います。

## 4. 直す

違反ごとに、行の中の文 (RULES.md の同じ番号の文と同じ) と直し方を読んで直します。直す前に、「何をどう直すか」を 1 行で担当者に伝えます。

- 直してよいのは、会社のシステムの置き場の中のファイルだけです。会社が足した画面、`fields/`、`templates/`、`checks.py` がこれに当たります。
- 違反のファイルが部品の中 (`seizou` の package。`site-packages/seizou/` の下や、部品のソースの置き場) にあるときは、直しません。そのことを担当者に伝えて止まります (R20。プラグインの hook も書き込みを止めます)。

直し方の例です。ほかの番号も、行の直し方のとおりに直します。

- R13 (数と金額を変える処理は部品の `services` の関数を通す): 画面から表に直接書いている所を、部品の `services` の関数を呼ぶ形にします。合う関数が部品に無ければ、直さずにそのことを伝えて止まります。
- R15 (画面は core の土台の画面を継承する): 画面を `seizou.core.views` の `Base*View` を継承する形にし、class の中で上書きする物を、決まりの文にある 11 の属性だけにします。

## 5. 回し直す

置き場で `<python> manage.py seizou_check` を回し直します。合計の行が「違反 0 件」で、終わりの番号が 0 になるまで、4 と 5 を繰り返します。3 回回し直しても 0 にならなければ、残った行をそのまま担当者に見せて止まります。

## 6. 確かめる

置き場で `<python> manage.py check` を回し、誤りが無いことを確かめます。

開発のサーバーが動いていれば、直したファイルを保存したときに自動で起動し直します。担当者に、ブラウザで読み込み直すと「決まりに沿っていません」の画面が消え、置き場の `.seizou/violations.md` も消えることを見てもらいます。開発のサーバーが一度も読んでいないファイルを直したときは、自動では起動し直しません。そのときは、開発のサーバーを止めて起動し直すよう担当者に頼みます。

## 7. 終わりに言うこと

次の 2 つを 3 行以内で伝えます。

- 直したファイルと、違反の番号
- 次にすること: 直した画面で同じ操作をして、決まりどおりに止まるかを見る

## してはいけないこと

- 部品の中身と RULES.md と決まりのテストを書き換えません (R20)。
- 黙らせる印 (`seizou: ignore[...]`) を足して、違反を通しません。
- 検査を無効にしません。検査の対象から外して通しません。`settings.py` の `BASE_DIR` と `MIDDLEWARE` を変えず、ファイルを `migrations` や `tests` の名前のフォルダへ動かしません。
- `.seizou/violations.md` を手で書き換えて済ませません。
- テストを消しません。
- 鍵と `.env` に触りません。
