# 説明書を書き起こす

この命令は、会社のシステムの画面ごとの使い方を、日本語の説明書として書き起こします。読む人は、工場で PC を任された担当者と、その会社で画面を使う人です。どちらもプログラムを書かない人です。担当者に見せる文と説明書の文は短く平易な日本語にし、専門の言葉を初めて使うときは短い説明を添えます。

## 1. 最初に言うこと

動き出す前に、次の趣旨を 1〜3 行で担当者に伝えます。

- この会社のシステムの画面ごとの使い方を、日本語の説明書として置き場の `manual/` に書きます。
- 画面を足したり変えたりした後に作り直すときも、同じ命令を打ちます。

## 2. 前提を確かめる

1. 会社のシステムの置き場は `~/seizou-sites/<id>/` です (`/seizou:build` が作った所。`<id>` は会社の id = 会社を見分ける短い名前)。今の作業のフォルダがそこでなければ、どの会社かを聞きます。候補は `~/seizou-sites/` の下のフォルダの名前です。
2. 置き場に `manage.py` と `answers.yaml` が無ければ、「先に `/seizou:build` で会社のシステムを立ち上げてください」の趣旨を伝えて止まります。
3. 置き場の `README.md` の「起動」にある 1 行 (`seizou new` が書いた `cd <置き場> && <python> manage.py runserver <port>`) を読み、`<python>` の所を覚えます。この後の `manage.py` は、いつもこの python で、置き場の中で打ちます。
4. 命令が見つからないときや失敗したときは、出力をそのまま担当者に見せて止まります。手で作業を補いません。

## 3. 読む

1. 画面の目録 (土台を継承した画面の一覧) を、次の命令で読みます。

```
<python> manage.py seizou_screens --format tsv
```

   - 1 行が 1 画面です。列はタブで区切られ、順に app・view・名前・1 文・URL の名前・道 (URL の形) です。
   - 説明書の章立ては、この行の順にします。
   - 目録に無い画面は書きません。
2. `answers.yaml` を読みます。使うのは、会社の名前 (`name`)・業種 (`industry`)・会社ごとの項目 (`item_fields`)・選べる設定 (`settings`) です。
3. 公開リポジトリ (seizou) の `RULES.md` が手元にあれば、決まりの番号と文を読みます。注意の行に引くためです。読めなければ、決まりの番号と、画面に出る知らせの文の範囲で書きます。
4. 画面の字 (見出し・ボタン・欄の名前・左のメニューの名前) は、画面そのものから取ります。
   - Playwright の道具 (ブラウザを動かす道具) がこの会話で使え、runserver が動いていれば、その画面を開いて見ます。
   - 使えなければ、部品の画面のテンプレートとコードを読みます。置き場は `<python> -c "import seizou; print(seizou.__path__[0])"` で分かります。読むだけで、書き換えません。
   - どちらでも確かめられない字は書きません。

## 4. 書く

画面の目録の 1 行ごとに、HTML の断片 (ページの一部だけの HTML) を 1 つ書きます。

- ファイルの名前は、URL の名前の `:` を `_` に替えた物です。例: URL の名前が `orders:order_list` なら `manual/orders_order_list.html` です。
- 中身は `<section>` 1 つで、次の順に並べます。

```
<section>
  <h2>(目録の名前のまま)</h2>
  <p>(何ができるか。目録の 1 文を元に書く)</p>
  <h3>道筋</h3>
  <p>(ログインの後の最初の画面 → 左のメニュー → この画面)</p>
  <h3>手順</h3>
  <ol>
    <li>(画面の字を「」でそのまま引いて、1 つの操作を書く)</li>
  </ol>
  <h3>注意</h3>
  <ul>
    <li>(決まりと、この会社の設定の値で変わる動き)</li>
  </ul>
  <h3>動作確認</h3>
  <table>
    <tr><th>操作</th><th>期待する結果</th></tr>
    <tr><td>(操作)</td><td>(期待する結果)</td></tr>
  </table>
  <img src="images/(断片と同じ名前).png" alt="(目録の名前)">
</section>
```

- 道筋: ログインの後の最初の画面は、目録の `core:home` の画面です。そこから左のメニューの入口を通って、この画面までの道を書きます。メニューに入口の無い画面 (詳細・入れる・直すの画面など) は、入口のある画面から、どの行やボタンを押すかまで書きます。
- 手順: 画面の字 (見出し・ボタン・欄の名前) を「」でそのまま引きます。数の在りかと単位も書きます (例: 残の数は、受注の数から出荷済みの数を引いた物)。
- 枠ごとの説明: 画面の中の枠 (ダッシュボードの節と、詳細の画面のタブ) には「?」のボタンがあり、押すとその枠の説明だけが小窓に出ます。枠の説明は、手順の後に `<h3 id="<枠の id>">(枠の名前)</h3>` の見出しと `<p>` で書きます。小窓は、その見出しから次の `<h3>` の前までを出します。画面の題は `<h2>` の 1 つだけにします (小窓の題にも使います)。枠の id の見出しが無い断片では、小窓に画面の説明の全部が出ます。
- 枠の id は画面の目録 (`seizou_screens`) に出ないので、次の表の物を使います。ブラウザで枠の「?」のボタンの `hx-get` の末尾 (`?part=<id>`) を見ても分かります。

| 画面 | 枠 | 枠の id |
|---|---|---|
| ダッシュボード (`core:home`) | 出荷の節 | `shipping` |
| ダッシュボード (`core:home`) | 生産の節 | `production` |
| ダッシュボード (`core:home`) | 最近の受注の節 | `recent-orders` |
| ダッシュボード (`core:home`) | 納期アラートの節 | `due-alerts` |
| ダッシュボード (`core:home`) | 注文の入口の節 | `inlets` |
| 詳細の画面 (`<app>:<model>_detail` の全部) | 基本情報のタブ | `basic` |
| 詳細の画面 (`<app>:<model>_detail` の全部) | 関係する物のタブ (タブがいくつあっても 1 つの枠) | `related` |

- 注意: 決まりは、`RULES.md` の文をそのまま引き、番号を添えます。
- 注意: 選べる設定の値を、その会社の値で文に出します。値は `answers.yaml` の `settings` にあり、意味は公開リポジトリの `README.md` の「選べる設定」の表にあります。
  - ポカよけ (間違いに気づかせる検査) の `over_shipment` と `over_workorder` は、値ごとに書き分けます。`stop` の会社は赤の知らせが出て保存されない、`warn` の会社は黄の知らせと「このまま保存」のボタンが出る、`off` の会社は知らせが出ずに保存される、と書きます。例: `over_shipment` が `stop` の会社では、「受注より多い出荷は赤の知らせで止まる」と書きます。`warn` の会社では、「黄の知らせと『このまま保存』のボタンが出る」と書きます。
  - ほかの設定 (`order_form`・`partial_shipment`・`order_number`・`hidden_fields`) も、値が変える画面の断片に、その会社の値で書きます。`hidden_fields` で隠した項目は書きません。
- 会社ごとの項目 (`item_fields`) は、部品マスターと品目の画面の断片に、項目の名前 (`label`) を並べます。
- 動作確認の表: 操作と期待する結果の 2 列です。画面ごとに、その画面で確かめられる操作を書きます。
- 絵: 6 節で撮った絵があるときだけ、`<img src="images/<断片と同じ名前>.png" alt="<画面の名前>">` を最後に置きます。絵が無ければ `<img>` を書きません。

## 5. 断片の決まり

- 素の HTML だけを書きます。`class` の属性、`<script>`、`<style>`、`{{`、`{%` を書きません。断片は、使い方のページが囲んで出す物です。画面の見た目のファイル (CSS) に無い class を作らないためにも、`class` を書きません。
- `<h3>` の `id` の属性だけは書きます (枠の「?」が読みます)。
- 作り物のデータ (`--demo` で入れた見本のデータ) の数を書いた断片には、「この説明書の数字は見本のデータの物です」の 1 行を `<p>` で足します。
- 作り直すときは、目録の全部の画面の断片を書き直します。目録に無い画面の断片が `manual/` に残っていれば、そのファイルの名前を担当者に伝えます。
- 書くのは `manual/` の中だけです。`manual/` の外に書きません。

## 6. 絵を撮る (任意)

- この会話で Playwright の道具が使え、runserver が動いているときだけ撮ります。
- ログインは、Playwright の道具が開いた窓で、担当者に自分でしてもらいます。パスワードは聞かず、打ちません。
- 絵は画面ごとに 1 枚で、置き場は `manual/images/<断片と同じ名前>.png` です。
- 作り物のデータを入れた会社 (`--demo` で立ち上げた会社) なら、絵に中身が入ります。データの無い会社なら、空の画面の絵になります。そのときは、データを入れた後に作り直せると伝えます。
- 道具が無いときや runserver が動いていないときは、絵を飛ばします。担当者には、後で同じ命令で作り直せると伝えます。
- 全部の画面をまとめて撮るなら、runserver を動かしたまま、置き場で `<python> manage.py seizou_manual_shots --base http://127.0.0.1:<ポート>` を打ちます (Playwright が要ります)。絵は `manual/images/<断片と同じ名前>.png` に入り、断片に `<img>` が無くても「使い方」の画面と印刷と冊子に付きます。
- 自動ログインの無い会社では `--user <ID>` を付け、パスワードは環境変数 `SEIZOU_SHOTS_PASSWORD` で渡します。担当者に自分の端末で打ってもらい、パスワードを聞きません。

## 7. 確かめる

置き場の中で、`ls` と `grep` で次の 3 つを確かめます。

1. 目録の全部の画面に断片があること。目録の行の URL の名前ごとに、`manual/<名前>.html` があるかを `ls manual/` で見ます。
2. 断片に `class=`・`{{`・`{%`・`<script`・`<style` が無いこと。`grep -l -e 'class=' -e '{{' -e '{%' -e '<script' -e '<style' manual/*.html` が何も出さなければ通ります。
3. `<img>` の絵のファイルがあること。`grep -o 'src="images/[^"]*"' manual/*.html` で出た名前が、`manual/images/` にあるかを `ls` で見ます。

足りない物があれば、書き足してから確かめ直します。

## 8. PDF を作る

確かめが通ったら、置き場の中で次の命令を打ちます。表紙と目次とページ番号の付いた冊子 (PDF) が `manual/使い方.pdf` にできます。

```
<python> manage.py seizou_manual_pdf
```

- 書き出し先を変えるときは `--out <パス>` を添えます。
- 「PDF の部品 (WeasyPrint) が使えません」と出たときは、PDF を飛ばし、出た 1 行をそのまま担当者に見せます。画面の「使い方」と印刷用の 1 枚はそのまま使えます。
- 冊子にも絵が入ります (断片が指す `images/<名前>.png` をそのまま読みます)。

## 9. 終わりに言うこと

「できた物」と「次にすること」を 3 行以内で伝えます。

- できた物は、書いた断片の置き場 (絶対パス) と数です。絵を撮ったときは、絵の数も伝えます。
- 書いた説明書は、会社のシステムの上の帯の「使い方」のボタン (`http://127.0.0.1:<port>/manual/`。`<port>` は `answers.yaml` の `port`) で読めること、印刷用の 1 枚はそのページの「印刷用を開く」(`/manual/?print=1`) で開けることを伝えます。PDF の冊子ができたときは、その場所 (`manual/使い方.pdf` の絶対パス) と、「使い方」のページの「PDF」のボタンでも同じ冊子を開けることを伝えます。
- 画面を変えた後は、同じ命令で作り直せると伝えます。

## してはいけないこと

- 無い機能を書きません。目録に無い画面を書きません。
- 部品の中身 (`seizou` の package) を書き換えません。
- 会社の設定 (`settings.py`・`answers.yaml`・`.env`) を書き換えません。`.env` は読みません。
- 実在の会社名と人名を書きません。
- 手元のほかのリポジトリと社内の文書を読みません。読むのは公開リポジトリと、会社のシステムの置き場だけです。
